## 1. 设计原则

1. 用户在模型选择器中选择的模型和推理强度，决定主 Agent 的模型和推理强度。
2. 角色只描述“子 Agent 做什么”，不绑定模型或推理强度。
3. 模型路由只描述“这个角色由什么模型、以什么推理强度运行”。
4. Sol 主 Agent 除 Ultra 外，不论用户选择 Low、Medium、High、XHigh 或 Max，都读取同一套 Sol 子 Agent 路由。
5. Astra 主 Agent 除 Ultra 外，不论用户选择 Low、Medium、High、XHigh 或 Max，都读取同一套 Astra 子 Agent 路由。
6. Ultra 保留用户选择的主 Agent 和原生委派语义，不得被普通 Sol/Astra 路由降级或替换。
7. 每次启动子 Agent 时显式传入模型和推理强度；角色文件保持模型中立。
8. 只并行执行互不依赖、边界明确的工作。任何时刻最多允许一个子 Agent 修改同一工作树。

## 9. 实施映射（确认后再执行）

角色和模型应按下列方式解耦：

- `.codex/agents/*.toml`：只保存角色职责、权限和工具约束，不保存 `model` 或 `model_reasoning_effort`。
- `AGENTS.md`：根据主 Agent 的模型族选择本表中的 Sol 或 Astra 路由，并在每次 spawn 时显式传入子 Agent 模型和推理强度。
- `.codex/config.toml`：只保存是否启用 multi-agent、并发上限和中断行为；如果采用显式路由，不设置全局默认子 Agent 模型与推理强度。
- Ultra：读取本表第 6 节，不被普通模型族路由覆盖。

对应的逻辑应是：

```text
读取用户选择的主 Agent
├─ Sol Ultra / Astra Ultra → 使用 Ultra 规则，保持主 Agent 不变
├─ Sol，其他推理强度     → 按角色读取 Sol 路由表
├─ Astra，其他推理强度   → 按角色读取 Astra 路由表
└─ 其他模型              → 使用通用回退规则
```
