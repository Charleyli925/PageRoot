# 顶部状态徽章 · 版本树 Hover 示意图

- 文档版本：PRD v0.3
- 最近更新：2026-08-15（Asia/Shanghai，UTC+8）
- 修订：v0.3 重画全部示意图。节点按固定列对齐；连线只落在内容父亲列。v0.2 的 F 图把 V7 接到 V3/V5、把 V8 接到 V7，作废。
- 状态：草案，待产品确认后实施
- 适用范围：桌面工作台标题栏状态区。当前 `main` 上该徽章默认沉默，只在保存、等 AI 或看历史时出字；本 hover 仍挂在同一状态区，不把「基于 Vn / 项目最新 Vm」重新做成常驻文案。
- 关联文档：[版本与项目文件产品需求](VERSION_AND_PROJECT_FILES_PRD.md)、[MVP 产品需求](MVP_PRD.md)、[交互流程](INTERACTION_FLOW.md)

本需求只增加一层**瞬时、只读、示意性**的版本树预览。它不改变正式版本、Working Copy、Candidate 或 Promotion 的任何规则。版本语义以 [VERSION_AND_PROJECT_FILES_PRD](VERSION_AND_PROJECT_FILES_PRD.md) 为准。

## 1. 为什么做

标题栏曾经用一句话交代三件事：

- 当前工作文件基于哪个正式版本
- 项目最新正式版本是哪一个
- 本地修改是否已保存

这句话对熟悉产品的人够用，但对第一次看到「基于 V2 · 项目最新 V6」的人几乎无法建立图像：版本是一条线，还是一棵树？我现在打开的是哪一个？本地修改长在哪里？

当前工作台已把这句常驻徽章收成默认沉默，只在保存、等 AI 或看历史时出字。右侧「版本历史」抽屉仍能回答这些问题，但成本太高：要点开面板、扫列表、展开条目。用户此刻只是想**扫一眼地图**。

因此：把标题栏状态区变成一个轻量入口。悬停即见图，移开即消失。图必须比那句话更直观，但不能比那句话更吵。

## 2. 产品结论

> 状态徽章负责「一句话」；Hover 示意图负责「一张版本树」。图只解释当前打开位置，不承担切换、编辑或审阅。

一句话必须同时成立：

1. 看见每一个已存在的正式版本，以及它们如何连成树。
2. 一眼认出**当前打开的是哪一个**。
3. 若当前不是最新正式版本，也能同时看见最新在哪里。
4. 连线只表示「内容从哪一版长出来」，不表示「序号谁挨着谁」。
5. 本地未晋升的修改、待审阅候选，只作为未发布的短枝，不伪装成正式版本。
6. 鼠标离开，图立刻收起。不钉住、不记住、不改任何状态。

## 3. 目标与非目标

### 3.1 目标

- 悬停标题栏状态徽章时，在其下方出现一张小版本树卡片。
- 横轴表示进度：版本序号越大，越靠右。V7 永远在 V6 右边，即使它的内容来自更早的版本。
- 纵轴表示分叉：一条内容线占一行；从旧版本重新长出来的新版本，必须开新行，只连到它真正基于的那一版。
- 当前打开与「项目最新」不是同一个标记。两者重合时只强调「当前」。
- 有本地已保存/保存中修改时，从当前基础版本长出「本地」短枝。
- 有待审阅或生成中的候选时，从该候选真正基于的版本长出「候选 Vn」虚节点；它不是正式版本。
- 只读浏览历史版本时，当前标记落在被查看的正式版本上，并标明只读。
- 指针离开徽章和卡片后，卡片消失；不留下遮罩、焦点锁或路由变化。
- 数据全部来自现有 Version / Working Copy / Candidate 投影，不新增权威存储。

### 3.2 非目标

- 不在这张图上点击切换版本、打开历史、采纳或拒绝候选。
- 不替代「版本历史」抽屉，也不成为第二个版本管理器。
- 不引入 Git 用户词：分支、合并、变基、HEAD、working tree、commit。内部实现可以按行列描述，界面不出现这些词。
- 不展示 Hash、Request ID、Attempt、文件路径、评论正文。
- 不提供搜索、筛选、缩放、小地图。
- 不在图上编辑、重命名、删除、钉住或分享版本。
- 不把每次自动保存画成新的正式节点。
- 不在浏览器预览页、AI 审阅主画布、欢迎页或无项目状态显示此 Hover。
- 不为触控设备单独做长按菜单；本产品以桌面指针为主。键盘可看见同一张图，但不能把 Hover 做成必须点击才能关闭的弹层。

## 4. 入口与出现条件

### 4.1 入口

唯一入口：标题栏文件名下方的状态徽章，即现有

```text
基于 V1 · 项目最新 V1 · 本地修改已保存
```

对应界面节点：`.file-version-label.project-status-facts`。

「在文件夹中打开」和「已安全保存」不是入口，也不被这张图替换。

### 4.2 何时可出现

同时满足：

- 当前已打开有效项目
- 至少存在正式版本 1
- 工作台处于可展示项目状态的编辑或只读浏览主界面
- 徽章本身可见

下列情况不出现：

- 项目正在加载、打开失败、工作区不可用
- 处于 AI 候选审阅工作区（那里的身份已经是「审阅 AI 候选」）
- 徽章被重命名输入框或其他瞬态 UI 挤掉

只有 V1、且当前就在 V1、无本地修改、无候选：仍显示一张单节点图。这是教学，不是无内容。

## 5. 图里到底画什么

### 5.1 节点种类

卡片最多四种节点，不允许第五种。

| 节点 | 用户看见 | 含义 | 何时出现 |
|---|---|---|---|
| 正式版本 | `V1` `V2` … | 不可变里程碑 | 每个已提交正式版本一枚 |
| 当前打开 | 实心强调环 + 短注 | 此刻画布对应的位置 | 始终恰好一枚 |
| 本地短枝 | `本地` | 基于某正式版本的工作文件，内容已与快照不同 | 仅当当前工作文件相对其基础版本有未晋升修改 |
| 候选短枝 | `候选 Vn` | AI 返回、尚未采纳 | 仅当存在待审阅或生成中的候选 |

被拒绝、失败、取消的候选不出现。它们从未成为历史事实。

### 5.2 当前打开如何判定

只使用现有界面事实，不发明第三套「当前版本」。

| 工作台状态 | 当前打开落点 | 短注 |
|---|---|---|
| 正在编辑某版本的工作文件 | `currentBasedOnVersionId` 对应节点 | 有本地修改时加「本地」短枝；与快照一致时不加短枝，只强调该节点 |
| 正在只读查看某正式版本 | `viewingVersionId` 对应节点 | 短注「只读」 |
| 项目最新正式版本恰好就是当前基础，且无本地修改 | 同一节点同时是当前与最新 | 不重复画两枚标记 |

「项目最新」用节点旁一枚极淡的 `最新` 字样标出，仅当它与当前打开不是同一节点时才出现。两者重合时，当前标记优先，不再写「最新」。

最新节点 = 序号最大的正式版本，不一定在第一行，也不一定在当前所在行。它通常是整张图最靠右的正式节点。

## 6. 布局几何：横轴进度，纵轴分行

这是本需求的核心。v0.1 把所有正式版本排在同一行、再用括号把 V2 连到 V7，是错的：V7 会看起来像从 V6 接着往下做。

正确图像必须让人在 1 秒内读出两件事：

- **谁比谁新**：看左右。
- **谁从谁长出来**：看连线。没有连线，就没有「接着做」的关系。

### 6.1 两个轴

| 轴 | 含义 | 规则 |
|---|---|---|
| 横轴 | 进度 / 新旧 | 列号 = 正式版本序号。`Vn` 固定在第 n 列。V7 永远在 V6 右侧。 |
| 纵轴 | 内容线 | 一行是一条内容线。从某版本分叉出去的新版本，开新行，只连接到它的内容父亲。 |

`previousVersionId` **不参与画线**。它只说明「时间上前一个正式版本是谁」，不能拿来把 V6 和 V7 连起来。

画线的唯一依据是 `basedOnVersionId`：

> 版本 N 有且仅有一条入边，从它真正基于的版本 K 指向 N。K 与 N 之间即使隔着 V3、V4、V5、V6，也不许把这些中间版本串进这条边。

### 6.2 行号怎么分

按序号从小到大放入节点：

1. V1 放在第 0 行、第 1 列。它是根，没有入边。
2. 对之后的每个正式版本 N，找到内容父亲 K = `basedOnVersionId`。
3. 把 N 的**内容子女**按序号排序。序号最小的那一个**留在父亲同一行**，这是这条线的自然延续。
4. 其余子女各自**新开一行**。新行插在父亲所在行的正下方，把更远的行往下推。不要追加到整张图最底部，否则后画的竖线会穿过先画的横线，看起来像连错了父亲。
5. 若两个分叉都要插到同一行下方：父亲列更靠右的那条更靠近父亲（竖线更短）；父亲相同则序号更小的更靠近父亲。
6. 若父亲不存在、指向自己、或指向比自己更新的版本：N 放在新行，不画入边。不猜测。

「第一子女留在原行」的直觉：最早从这里继续做下去的那一版，还是这条线；后来又回到这里重做的版本，才是下面那一行。

### 6.3 边怎么走

同一行的父子：画一条水平细线，从父亲圆心到子女圆心。中间若有空列（那些序号的版本在别的行），线直接跨过去，空列不打点。

不同行的父子：画圆角折线，只有两段：

1. 在父亲所在列，从父亲垂直落到子女所在行。
2. 再水平走到子女。

禁止：

- 把 V6 连到 V7，除非 V7 的 `basedOnVersionId` 就是 V6
- 用跨越整段主轴的大括号、方括号、阴影带来暗示「从 V2 跳到 V7」
- 斜向穿越其他节点圆心
- 为了「看起来连续」而把没有父子关系的相邻序号连起来

折线可以在父亲列上重叠成一根主干，看起来像从父亲向下分出若干行。不要为每个子女各画一根完全错开的竖线。

两线交叉且交叉处没有节点，只是穿过，不是连接。实现里交叉处不打点。示意图为免误读，按第 6.2 节把较右父亲的分叉画得更靠上，让竖线少穿过别人的横线。

### 6.4 本地短枝与候选短枝

它们不是正式版本，不占用「第 n 列属于 Vn」这个约定之外的正式列。

**本地**

- 挂在当前工作文件对应的正式版本 K 上。
- 若 K 在本行右侧已经有正式子女：本地在 K 下方再开一行微枝，仍停在 K 这一列附近，不要画到下一个正式版本的列里。
- 若 K 是本行最右的正式节点：本地作为更小的节点，在同一行向右伸出半列，标签 `本地`。

**候选 Vn**

- 按正式版本同样的父子规则投影：父亲是该候选的 `basedOnVersionId`，列号是候选序号。
- 因为它还不是正式版本：圆点更小、连线用虚线、标签写 `候选 Vn`。
- 若同一父亲上已经有「本地」，候选接在本地之后，仍用虚线，表示「这一轮还没成为正式版本」。
- 候选列若与已存在的正式版本列冲突（不应发生；候选序号未被占用），则改到该行最右侧空半列，并在说明行写清 `候选 Vn`。不覆盖正式节点。

被拒绝的候选不占行、不占列。

### 6.5 标准情形

以下全部按真实字段画，不按「看起来顺」。

示意图用固定列网格，避免汉字把竖线挤到别人头上：

- 第一行是列头。`Vn` 只标明这一列是谁，不是节点。
- `*` 正式版本，`@` 当前打开，`o` 尚未采纳的候选，`L` 本地修改。
- `|` `+` `-` `.` 是连线。交叉处没有 `*` / `@` / `o` / `L`，就不是连接。
- 每个节点的 `*` / `@` / `o` 必须落在自己列头正下方。V7 的点若出现在 V6 列，就是画错了。

#### A. 一条线

V1 到 V6 都基于前一正式版本。当前打开 V6，无本地修改。

```text
V1  V2  V3  V4  V5  V6
*---*---*---*---*---@
```

只有一行。当前就是最新，不必再标「最新」。

#### B. 回到旧版继续改，尚未形成新正式版本

最新 V6，当前基于 V2，有本地修改，候选 V7 待审阅。

```text
V1  V2  V3  V4  V5  V6  V7
*---@---*---*---*---*
    |
    +--L................o
```

- `@` 在 V2：当前打开基于 V2。
- 第一行 V3 到 V6 仍在，因为那是已经发生的内容线。
- `L` 和候选 `o` 都从 V2 落下，只连 V2。
- V6 与候选 V7 之间没有线。项目最新是 V6。

#### C. 采纳后，V7 基于 V2

V7.`basedOnVersionId` = V2，V7.`previousVersionId` = V6。当前打开 V7。

```text
V1  V2  V3  V4  V5  V6  V7
*---*---*---*---*---*
    |
    +-------------------@
```

读法：V7 在 V7 列（最右，所以最新），在第二行（所以不是从 V6 长出来的），竖线在 V2 列（所以只基于 V2）。**V6 列到 V7 列的第一行没有横线。**

禁止：

```text
V1  V2  V3  V4  V5  V6  V7
*---*---*---*---*---*---@
```

禁止：把竖线画在 V3 列、V5 列，或从 V7 再往下连到别人。

#### D. 在新线上继续

V7 基于 V2，V8 基于 V7，V9 基于 V8。当前打开 V9。

```text
V1  V2  V3  V4  V5  V6  V7  V8  V9
*---*---*---*---*---*
    |
    +-------------------*---*---@
```

第一行停在 V6。第二行是 V2 长出的新内容线。V6 不连 V7。

#### E. 同一旧版上再次分叉

V7 基于 V2，V8 也基于 V2。当前打开 V8，最新是 V8。

```text
V1  V2  V3  V4  V5  V6  V7  V8
*---*---*---*---*---*
    |
    +-------------------*
    |
    +-----------------------@
```

两行分叉的 `+` 都在 V2 列，不在 V7 列。第二根竖线如果画在 V7 下面，就会误读成 V8 基于 V7。

#### F. 两个不同的旧版分别长出新版

V7 基于 V2，V8 基于 V4。当前打开 V8。

```text
V1  V2  V3  V4  V5  V6  V7  V8
*---*---*---*---*---*
    |       |
    |       +---------------@
    |
    +-------------------*
```

- `@` 在 V8 列，从 V4 落下：V8 基于 V4。
- `*` 在 V7 列，从 V2 落下：V7 基于 V2。
- V8 行更靠上，因为父亲 V4 比 V2 更靠右；这样 V4 的竖线不必穿过 V7 的横线。
- V7 与 V8 不共用一行，中间也没有从 V7 落到 V8 的竖线。

禁止（这是 v0.1 画错的那种）：

```text
V1  V2  V3  V4  V5  V6  V7  V8
*---*---*---*---*---*
        |       |
        +-------*           ← V7 错接到 V3/V5
                |
                +-----------@  ← V8 错接到 V7
```

#### G. 主线后来又往前走

V7 基于 V2 且已被采纳；之后又从 V6 采纳出 V9（V9 基于 V6）。当前打开 V7，最新是 V9。

```text
V1  V2  V3  V4  V5  V6  V7  V8  V9
*---*---*---*---*---*-----------*
    |
    +-------------------@
```

V9 是 V6 的第一内容子女，因此留在第一行，横线从 V6 跨过空的 V7、V8 列到达 V9。当前在第二行 V7。第一行 V6 到 V9 的线不经过 V7 的点。

#### H. 只读查看旧版

同 C，但用户正在只读查看 V3。

```text
V1  V2  V3  V4  V5  V6  V7
*---*---@---*---*---*
    |
    +-------------------*
```

`@` 在 V3：只读查看 V3。无本地短枝。最新是 V7，在第二行最右。

#### I. 复杂树

正式版本 V1…V12。

- V1–V5 依次基于前一版
- V6、V7 都基于 V3（V3 的第一子女仍是 V4，所以这两枚都开新行）
- V8 基于 V7，V9 基于 V8，V10 基于 V9
- V11 基于 V5（V5 尚无内容子女，V11 留在第一行）
- V12 基于 V10（接在 V10 同一行）

当前打开 V10，最新 V12。

```text
V1  V2  V3  V4  V5  V6  V7  V8  V9  V10 V11 V12
*---*---*---*---*-----------------------*
        |
        +-----------*
        |
        +---------------*---*---*---@-------*
```

- V11 在第一行 V11 列，只通过长横线连 V5，不经过 V10。
- V12 在第二内容线最右，连 V10，不连 V11。
- V6 只连 V3；V7 只连 V3；V6 与 V7 之间无线。

### 6.6 版本很多时

列可以压缩，行尽量不压缩。压缩后仍必须能看见当前打开、项目最新、以及把它们连回根的路径。

| 正式版本数 | 列 | 行 |
|---|---|---|
| 1–10 | 全画 | 全画 |
| 11–16 | 全画；卡片内可横向轻滑 | 全画；卡片内可纵向轻滑 |
| 17+ | 见下方保留集，其余列收成 `···` | 超过 5 行时，优先保证含当前与最新的行可见，其余行可纵向轻滑 |

17+ 列的保留集，缺一不可：

- 第 1 列（V1）
- 当前打开所在列
- 最新所在列
- 当前打开与最新各自一路走到 V1 经过的每一列
- 任何仍要画出的边的两个端点列

连续被省略的列收成**一个** `···`，宽度约一列。穿过省略区的水平线继续画，不在省略区打点。`···` 不可点，不代表某个版本。

若某条圆角折线的父亲或子女被省略，则这条边改为「从保留的祖先连到保留的后代」，不得悬空。宁可变宽横滑，也不许出现没有端点的线。

行不因折叠而合并。两条不同内容线始终两行。

### 6.7 必须为真的几何不变量

实现和测试按这些断言，而不是按截图像素：

1. 每个正式版本恰好一个节点，列号 = 序号。
2. 当前打开标记恰好一个。
3. 「最新」标签至多一个；仅当最新 ≠ 当前打开时出现。
4. 版本 N 的入边条数为 0 或 1。入边父亲必须是 `basedOnVersionId`。
5. 不存在「序号相邻因此相连」的边。
6. 若 N 基于 K，且 K 与 N 不同行，则 N 不得与 K 的第一内容子女排在同一行。
7. 本地短枝至多一个；候选短枝至多一个。
8. 候选节点不是正式版本节点，不进入「正式版本节点数 = 已提交正式版本数」的计数。
9. 布局不因「谁是当前打开」而重排行号。当前只改变强调，不改变树的形状。切换当前后，V7 还在原来那一行、原来那一列。

## 7. 视觉原则

这张卡必须像 PageRoot 自己长出来的：一张安静的小地图，不是 Git 客户端，也不是通用 tooltip。

### 7.1 气质

- 纸色底 `#fffefa`，细线，一层很浅的阴影。圆角 12px。
- 与标题栏徽章同一套石墨灰。当前打开是全图唯一重色，用品牌紫。
- 最新（若与当前不同）只用淡标签，不上第二种彩色。
- 正式连线 1px 实线，色 `#C8C9CE`。候选连线同色 1px 虚线。
- 折线转角用 6px 圆角，不要直角，不要箭头。
- 禁止 3D、渐变光晕、网格、节点投影、流动描边、emoji。

### 7.2 节点

- 正式版本：7–8px 圆点。未打开为浅灰实心；当前为紫色实心，外加 2px 柔环。标签 `Vn` 在点下方，11px，字重 560；当前为 650。
- 本地 / 候选：5px 圆点，标签同样在下方。候选圆点为空心或浅虚边。
- 点与标签垂直对齐到列中心。同一列的不同行，点的 x 必须对齐。这是「越右越新」能被看出来的前提。
- 行距 28–32px。列距 36–40px。不要更密。

### 7.3 卡片结构

从上到下：

1. 标题 `版本树`，12px，字重 650，颜色接近标题栏文件名。
2. 一行说明，11px，石墨灰，见第 9 节。
3. 树本身，左右留白 16px，上下留白 12px。

不要图例。树自己要能看懂。若必须解释「虚线是候选」，说明行已经写了 `候选 V7 待审阅`。

### 7.4 尺寸与位置

- 卡片是小面板，不是抽屉，不是模态。
- 默认出现在徽章正下方、左对齐，间隙 6–8px。
- 默认最大约 440×260。树超出时在卡片**内部**滚动，出现极淡滚动条或无滚动条的触控板滚动。不撑破窗口，不出现页面级横向滚动。
- 靠近右缘时改为右对齐徽章。垂直空间不足时可翻到徽章上方。
- 不得挡住文件名。

打开时，优先把当前打开节点滚进卡片可视区；若当前与最新不能同时看见，优先保证当前，最新仍可通过轻滑到达。

### 7.5 动效

- 出现：160ms 淡入 + 2px 下移。
- 消失：120ms 淡出。
- 树本身不再做逐点蹦出。连线与节点同时显现。
- 尊重 `prefers-reduced-motion`：无位移，≤80ms 淡变或即时显隐。

## 8. 交互合同

### 8.1 指针

- 鼠标进入徽章：延迟 180ms 后显示，避免划过误触。
- 鼠标从徽章移入卡片：卡片保持。间隙视为安全区。
- 鼠标离开徽章且离开卡片：延迟 120ms 后隐藏。若在这 120ms 内回到任一区域，取消隐藏。
- 出现期间移动窗口、切换项目、打开抽屉、进入审阅：立即隐藏。
- 滚动画布：隐藏。版本树不钉在画布上。
- 卡片内部滚动树：不关闭卡片。

### 8.2 明确不做的指针行为

- 单击徽章仍什么都不做。它不是按钮，不打开抽屉，不切换版本。
- 单击卡片空白或节点：不响应。这不是可点的地图。
- 不支持拖拽、框选、双击、右键菜单。
- 不在卡片出现时改变徽章文案。

### 8.3 键盘与辅助技术

- 徽章可被 Tab 聚焦。聚焦时显示同一张卡；失焦且指针也不在卡上时隐藏。
- `Escape` 立即隐藏。
- 卡片 `role="tooltip"`（或等价的只读描述），由徽章的 `aria-describedby` 指向。
- 屏幕阅读器不朗读坐标，只朗读标题 `版本树` 加说明行那一句完整事实。
- 当前打开同时有环和短注，不只靠颜色。

### 8.4 与现有入口的分工

| 入口 | 职责 |
|---|---|
| 状态徽章一句话 | 持续可见的压缩事实 |
| 本 Hover 版本树 | 瞬时建立空间直觉 |
| 版本历史抽屉 | 查看详情、只读打开某版本、在 Finder 中显示 |

三层不得互相抢文案。Hover 里如果开始出现「查看此版本」「继续编辑」按钮，就说明做超了。

## 9. 文案

用户可见词表只准用这些：

- `版本树`（卡片标题，用户可见名称）
- `V1` `V2` …（与现有徽章同一套压缩写法）
- `当前` `最新` `只读` `本地` `候选 Vn` `待审阅` `生成中`
- 说明行中的 `基于` `项目最新` `与正式版本一致` `有本地修改` `正在查看`

说明行：

| 情境 | 说明行 |
|---|---|
| 当前即最新，无本地修改 | `当前 V1，与正式版本一致` |
| 当前即最新，有本地修改 | `当前基于 V1，有本地修改` |
| 当前不是最新 | `当前基于 V2 · 项目最新 V6` |
| 只读浏览 | `正在查看 V2 · 只读` |
| 有待审阅候选 | 在上述句子末尾追加 `· 候选 V7 待审阅` |
| 有生成中候选 | 在上述句子末尾追加 `· 候选 V7 生成中` |

禁止出现：

- Working Copy、Promotion、ordinal、HEAD、branch、commit、DAG
- `ver_0002` 等内部 ID
- `版本谱系`（不再用作界面标题）
- 「分叉」「合并」作为界面标题或节点标签

「版本树」是这张卡的名字。用户不需要先懂内部字段，只需要看见树。

## 10. 数据与正确性

卡片是纯展示。输入仅包括：

- 已提交正式版本列表：`id`、`ordinal`、`basedOnVersionId`
- `previousVersionId` 可传入，但**布局与连线必须忽略它**
- `latestVersionId`
- `currentBasedOnVersionId`
- `currentExactVersionId`
- `viewMode` / `viewingVersionId`
- 当前工作文件是否相对基础版本有未晋升修改
- 当前 Candidate 的序号、`basedOnVersionId` 与状态（仅 `ready-to-open` / `processing`）

禁止为这张图额外读写 `.pageroot/`，禁止新建 Schema。几何是 UI 投影，不写进协议。

## 11. 验收

### 11.1 必须通过

1. 新项目仅 V1、无本地修改：单节点，当前打开在 V1，无短枝，无「最新」标签。
2. 在 V1 上本地编辑并已保存：V1 右侧或下方出现「本地」；徽章原文不变。
3. 线性 V1–V6，当前 V6：一行六列，相邻正式版本之间才有实线。
4. 最新 V6、当前基于 V2、有本地修改：第一行 V1–V6；第二行只从 V2 长出「本地」。V6 标「最新」。V2 与 V3 仍相连，因为那是原线。
5. 上例再加候选 V7 待审阅：候选在新行，虚线只连 V2。V6 与候选 V7 之间没有线。
6. 采纳后正式 V7 基于 V2：V7 在第 7 列、新行，入边只来自 V2。V6–V7 无线。当前打开在 V7。
7. V7 基于 V2，V8 基于 V7：第二行为 `V7 —— V8`，仍不与 V6 相连。
8. V7 与 V8 都基于 V2：两行分叉都只连 V2，V7 与 V8 无线。
9. V7 基于 V2、V8 基于 V4：两行不得合并；不得出现 V7–V8 连线。
10. 只读查看 V3：当前环在 V3，短注「只读」，无本地短枝。
11. 切换当前打开只改变强调，不改变任一节点的行列。
12. 鼠标移出后卡片消失；内部滚动位置不需要跨次悬停保留。
13. 打开版本历史抽屉、切换项目、进入审阅：卡片立即关闭。
14. 单击徽章、单击节点：不切换版本，不打开抽屉。
15. 屏幕阅读器听到 `版本树` 加一句完整说明，不会把每个 `Vn` 读成独立按钮。

### 11.2 明确失败

- 把本地修改画成 `V1.1` 或新的正式节点。
- 把待审阅候选画成实心正式节点，或接到最新正式版本后面。
- 因为序号相邻，就把 V6 连到基于 V2 的 V7。
- 用大括号、底托、阴影带代替真正的父子折线。
- 竖线或折点画在 V3、V5 等「看起来顺」的列上，而不是 `basedOnVersionId` 那一列。
- 从 V7 再向下连到 V8，只因为 V8 画在下一行。
- 为了「好看」删除 V3–V6。
- 因为当前在 V7，就把第一行改画成 V1–V2–V7，丢掉已经存在的 V3–V6。
- 出现后必须点空白才能关掉。
- Hover 里出现任何操作按钮。

## 12. 实施边界

- 只改工作台标题栏状态徽章的呈现层。
- 不改 VersionSession 权威状态，不改保存、打开、Promotion。
- 不把行列几何写进协议或 Schema。
- 现有 `projectStatusProjection` 的一句话继续做徽章正文；卡片说明行可以复用同一套事实，但不要把徽章改成「把鼠标放上来看版本」。
- 测试优先覆盖纯函数投影：给定版本列表与当前状态，输出每个节点的 `(列, 行)`、入边父亲、当前落点、最新落点、本地/候选短枝。必须包含第 6.5 节 C、E、F、G。界面测试覆盖显隐，不锁死像素级动画。

## 13. 以后可以做、现在不做

确认本需求做完且不添乱之后，才允许讨论：

- 悬停某个节点时显示一行更细的说明（例如「从 V2 继续」）
- 按住修饰键点击节点，等价于打开版本历史并定位到该项
- 把同一套版本树嵌进版本历史抽屉顶部

这些都不是 v0.2。v0.2 成功的标准是：用户把鼠标放上去，看见一棵安静的树，立刻知道自己在哪一条线、哪一个点，然后把鼠标移开，继续改页面。
