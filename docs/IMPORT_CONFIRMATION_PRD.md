# 首次打开导入确认

- 文档版本：PRD v1.0
- 最近更新：2026-08-16（Asia/Shanghai，UTC+8）
- 状态：产品规则已确认，待按 [修改计划](IMPORT_CONFIRMATION_PLAN.md) 实施
- 适用范围：桌面版打开尚未纳入 PageRoot 项目管理的本地 `.html` / `.htm`
- 关联文档：[版本与项目文件产品需求](VERSION_AND_PROJECT_FILES_PRD.md)、[MVP 产品需求](MVP_PRD.md)、[交互流程](INTERACTION_FLOW.md)、[安全模型](SECURITY_MODEL.md)、[ADR 0022](decisions/0022-user-owned-project-root-identity.md)

本文是首次打开外部 HTML 的产品规范。它修正现行「选中即自动导入、界面几乎不解释文件去向」的行为，不改正式版本编号、Working Copy、Candidate 或 Promotion 的其他规则。版本语义仍以 [VERSION_AND_PROJECT_FILES_PRD](VERSION_AND_PROJECT_FILES_PRD.md) 为准。

实施完成前，生产代码仍为自动导入且不删除原稿。实施同一 PR 必须把本文与被它取代的条款一并改到现行文档中，不能让「自动导入」和「先确认再导入」同时作为当前行为存在。

## 1. 为什么做

用户的默认心智是：打开 `产品首页.html`，之后改的就是这一份。

当前桌面打开路径不是这样。未登记的 HTML 会被立刻复制进 `~/Documents/PageRoot/项目/`，改名为 `<主干>-V1.html`，画布切到副本；原稿留在原地。成功提示只说「已打开 / 原来的文件没有改动」，既没有问过用户，也没有说清以后要去哪个文件夹找文件。

结果是：

1. 用户以为自己还在改下载目录里的那一份。
2. 文件名自己多了 `-V1`，路径也换了。
3. 再打开原稿会再导入成另一个项目。
4. 同目录图片、CSS、JS 不会跟着走，但界面没有预先说明。

PageRoot 仍然需要自己的项目文件夹来放版本工作文件和采纳后的 AI 新版本。要改的不是「有没有项目目录」，而是**第一次把文件纳进这个目录时，必须先讲清楚，并让用户决定原稿是否删除**。

## 2. 产品结论

> 打开一份还不是 PageRoot 项目的 HTML 时，先问再导入。默认只复制；只有用户勾选「成功导入后删除原文件」，才在导入成功之后删除原稿。最初版固定为版本 1。

必须同时成立：

1. 有效 v4 Project 仍直接打开，不再问导入。
2. 任何其他 HTML（全新文件、损坏的 v4、v4 以前的项目状态、项目里未登记的额外 HTML、未登记的项目副本）都先出现确认框，得到「导入并打开」之后才建立新的 v4 Project 与可见 `…-V1.html`。
3. 取消则不导入、不删除、不改名，也不把这份外部文件变成当前编辑目标。
4. 默认不勾选删除。勾选状态每次打开都从空开始，不跨文件、不跨会话记住。
5. 删除只针对刚才选中的那一份 HTML，且只发生在导入已经完整成功之后。删除失败不回滚已经导入的项目。
6. 最初正式版本是版本 1，可见工作文件是 `<主干>-V1.html`。第一次采纳 AI 才出现 `-V2.html`。不使用 `v0` 或 `V1.1`。

## 3. 目标与非目标

### 3.1 目标

- 用户在导入前就知道：文件会进入 PageRoot 项目管理，权威位置是文稿里的项目文件夹。
- 用户知道最初版本叫什么，以及以后采纳的 AI 修改版也会写在同一文件夹并按 `-V2`、`-V3` 命名。
- 用户知道同目录资源不会一起导入。
- 用户能选择保留原稿或在成功导入后删除原稿；默认保留。
- 取消导入的代价为零：原文件不变，当前已打开项目不变。
- 导入成功后，当前打开目标是项目里的 V1 工作文件，不是原稿路径。
- 原稿删除是窄权限、可失败、可解释的一步，不能变成任意路径删除。

### 3.2 非目标

- 不把原稿直接 `mv` 进项目文件夹。导入始终先在项目目录内发布完整 v4 项目；删除是可选的后置步骤。
- 不导入、不移动、不改写同目录图片、CSS、JS 或其他相对资源。
- 不在确认框里预览页面，也不在确认前把外部 HTML 挂到编辑画布。
- 不询问项目名称、存储位置或版本号。项目文件夹名与 V1 文件名仍按现有规则自动分配。
- 不把「版本」改成从 0 起算，也不把本地保存或「发给 AI」当成新正式版本。
- 不在确认框里解释 `.pageroot/`、Registry、Working Copy、Hash 或隐藏快照。
- 不为「可能以前导入过同名/同内容文件」做去重、合并或二次确认。Hash 相同不是同一项目。
- 不把勾选「删除原文件」记成用户偏好。
- 不在纯浏览器预览里做导入或删除。
- 不改变欢迎项目的首次自动建立。
- 不把待审阅 Candidate 说成已经出现在项目文件夹里的正式 `-Vn.html`。

## 4. 确认框

### 4.1 固定文案

外部 HTML 的确认框使用下面这段文案。除第一节标明的替换项外，标点、换行和用词不得改写。

```text
要把「产品首页.html」导入 PageRoot 吗？
会在「文稿 › PageRoot › 项目」里创建新项目，最初版本保存为 产品首页-V1.html。
之后请在这个文件夹里找文件；后续你采纳的 AI 修改版也会存在这里，并自动命名为 -V2、-V3。
同目录的图片等资源不会一起导入。

☐ 成功导入后删除原文件

［取消］［导入并打开］
```

替换规则：

| 位置 | 规则 | 例子 |
|---|---|---|
| 「产品首页.html」 | 用户选中文件的当前主文件名，含扩展名，不含目录 | `报告.htm` → 「报告.htm」 |
| 文稿 › PageRoot › 项目 | 见 §4.2 | 默认项目根 |
| 产品首页-V1.html | 本次导入将创建的可见 V1 工作文件名，必须与 Repository 实际命名函数一致 | `报告.htm` → `报告-V1.htm` |

「-V2、-V3」是说明后续采纳后的命名方式，不替换成具体文件名，也不预告下一个 ordinal。

### 4.2 项目根面包屑

默认配置项目根 `~/Documents/PageRoot/项目` 显示为：

```text
文稿 › PageRoot › 项目
```

不显示即将创建的项目文件夹名，例如不要写成「文稿 › PageRoot › 项目 › 产品首页」。同名时真实目录可能是 `产品首页 (2)`，确认框不提前占用或展示该名称。

若运行时配置了非默认项目根，则按该根的用户可见路径做同样的 ` › ` 面包屑，不出现环境变量名或内部标识。测试隔离目录属于这一支。

### 4.3 控件

| 控件 | 规则 |
|---|---|
| 复选框「成功导入后删除原文件」 | 每次打开确认框都未勾选。切换待确认文件时恢复未勾选。不写入偏好、Registry 或项目记录。 |
| 取消 | 关闭确认框，见 §6。 |
| 导入并打开 | 主按钮。无论复选框是否勾选，文案都是「导入并打开」。 |
| Escape | 与取消相同。 |
| 点按遮罩 | 与取消相同。 |
| Enter | 激活主按钮，导入并打开。 |

视觉复用现有审阅确认框（`confirmDialog`）：应用内模态，不是 macOS `showMessageBox`。冷启动外部打开也等渲染器就绪后用同一块确认框，不为启动路径做第二套原生文案。

确认框打开时，画布仍显示**当前已经打开的项目**（或欢迎项目），不闪入外部 HTML，也不出现空白「即将导入」页。

### 4.4 文案要说准的事实

「后续你采纳的 AI 修改版也会存在这里，并自动命名为 -V2、-V3」只指用户**明确采纳**之后，项目根目录出现的下一份正式工作文件。它不表示：

- 点击「发给 AI」就会多一份新文件；
- AI 一返回，磁盘上就已经是正式版本；
- 待审阅文件是用户现在要找的权威 HTML。

待审阅文件可以按既有 PR 2B 规则出现在 `AI任务/` 派生目录，但确认框不提 `AI任务/`、Candidate 或「待审阅」。

## 5. 何时出现，何时不出现

### 5.1 要出现

在桌面版，主进程已经得到一份绝对路径的 `.html` / `.htm`，且 `ProjectFileRepository.resolveOpenTarget` 不能把它绑定为有效 v4 Project 时出现。入口包括：

- 文件菜单「打开本地 HTML」
- 标题栏「+」
- 系统「打开方式」、双击、Dock 或命令行把 HTML 交给 PageRoot
- 打开项目文件夹里未登记的额外 HTML
- 打开未登记项目副本里的 HTML
- 打开 v4 以前的项目状态里的 HTML

这些入口共用同一确认框和同一后续导入事务。

### 5.2 不出现

| 情况 | 行为 |
|---|---|
| 有效 v4 Working Copy 或已登记项目的精确打开 | 按现有项目绑定和恢复，不问导入 |
| 从项目目录点选已登记项目 | 只提交 `projectId`，重验后打开 |
| 启动恢复上次的已登记项目 | 直接恢复 |
| 桌面首次启动自动建立欢迎项目 | 仍按欢迎项目流程登记 V1，不走本确认框 |
| 纯浏览器预览 | 无导入、无删除 |
| 用户在文件选择器点取消 | 现有行为：不打开新文件，不进入确认框 |

欢迎项目一旦已经是有效 v4 Project，之后再打开它也不走本确认框。

### 5.3 分类先于任何写入

确认框出现之前只允许：

1. 校验绝对路径、扩展名和可读性；
2. 用 Registry + manifest 判断是否有效 v4 Project；
3. 用与导入相同的纯函数计算将要展示的 V1 文件名和项目根面包屑。

确认框出现之前禁止：

- 调用 `importExternal` 或写入 Registry / `pendingImports`；
- 把外部路径写成当前活动文件或最近项目；
- 把外部 HTML 发布到 `DocumentSession` 或画布；
- 删除或改名原稿；
- 创建项目文件夹或 staging 目录。

## 6. 取消

取消、Escape、点按遮罩的结果相同：

1. 不导入，不创建项目，不写 Registry。
2. 不删除、不改名、不移动原稿。
3. 不把这份外部文件设为当前源，也不写入 Recent。
4. 若当时已有打开的项目（含欢迎项目），继续留在该项目，画布不变。
5. 丢弃本次待确认请求。之后要导入，必须重新选择或再次从外部打开。

进程在确认框打开时退出：视为取消。下次启动只恢复上次已经成功打开的已登记项目或欢迎项目，不恢复「差一点导入」的外部路径，也不自动弹出该确认框。退出前若外部打开已经写入 close-commit 的一次性 handoff，handoff 仍只保存已验证路径；下次启动必须重新走确认框，不得把 handoff 当成已经同意导入。

## 7. 导入并打开

用户点击「导入并打开」后，顺序固定为：

```text
再次读取外部 HTML 并校验未被确认框打开期间改掉
  → 按现行 v4 导入事务复制字节，发布项目根、隐藏 V1 快照、可见 V1 工作文件和 Registry
  → 当前打开目标切换到可见 V1 工作文件
  → 若勾选了删除：仅删除刚才那份外部 HTML（见 §8）
  → 显示成功结果
```

导入事务本身仍遵守 [VERSION_AND_PROJECT_FILES_PRD §7.2](VERSION_AND_PROJECT_FILES_PRD.md) 的原子性：任一步失败则原外部文件保持不变，不宣布导入成功，不留下已注册但不可打开的项目。可见工作文件名为 `<首选主干>-V1.<原扩展名>`，扩展名只允许 `.html` / `.htm`。

成功后的权威文件是项目里的 V1 工作文件。之后的直接编辑、自动保存、评论、附件和 AI 请求都只针对这个新项目。

确认框打开期间外部 HTML 的 Hash 变了：导入失败关闭，原稿不动，当前项目不动，说明「文件在确认期间被修改，没有导入」。用户可重新打开。

## 8. 成功导入后删除原文件

### 8.1 产品含义

默认不删除。只有确认框里勾选了该复选框，并且 v4 项目已经完整发布、当前目标已经切到 V1 工作文件之后，才删除**原位置上的那一份 HTML**。

这不是把原稿移动成 V1 工作文件。V1 工作文件永远是项目目录里新发布的那一份；删除只是去掉用户不再需要的外部正本。

同目录其他文件一律不动。

### 8.2 删除方式

在 macOS 上，「删除」实现为把该 HTML **移入废纸篓**，不是直接 `unlink`。用户还可以从废纸篓找回。

废纸篓不可用、权限不足、文件已经不在原路径、类型不再是普通文件、或路径校验失败时：删除失败，见 §8.4。

### 8.3 允许删除的唯一对象

只允许删除同时满足以下条件的文件：

1. 就是本轮待确认请求里、主进程已经验证过的那条绝对路径；
2. 本轮 `importExternal` 已经成功，且导入时记录的外部源 Hash 仍等于删除前再次读取的 Hash；
3. 它是普通文件，不是目录、不是软链接；
4. 它的真实路径不落在配置项目根之内，也不是本轮新发布的 V1 工作文件或隐藏快照。

Renderer 不得提供任意路径。删除命令只携带本轮不透明请求 ID 和「用户勾选了删除」这一比特；路径由主进程从该请求取出。

### 8.4 删除失败不回滚导入

项目导入成功后，删除原稿失败也**不得**删除或回滚已经发布的项目。界面说明：

> 项目已导入。原文件未能删除，仍留在原来的位置。

用户继续编辑项目里的 V1。不自动重试删除。

进程若在「导入成功」和「删除完成」之间崩溃：项目已经存在，原稿仍在。这是可接受的。下次再打开原稿，会再次出现确认框，因为原稿仍是外部 HTML。

### 8.5 不删除的情况

未勾选、用户取消、导入失败、Hash 已变、路径越权、目标是项目内文件：都不删除。

## 9. 成功之后怎么说

导入成功后，版本区按既有第二期规则显示「版本 1 · 已导入 PageRoot」，并提供「在文件夹中打开」。第一次成功再给一次短时成功提示，避免用户还要靠记忆去找文稿路径。

| 删除勾选 | 成功提示 |
|---|---|
| 未勾选 | 标题「已导入 PageRoot」；正文「最初版本已保存为 \<V1 文件名\>。原来的文件没有改动。」主操作「在文件夹中打开」 |
| 勾选且废纸篓成功 | 标题「已导入 PageRoot」；正文「最初版本已保存为 \<V1 文件名\>。原文件已移入废纸篓。」主操作「在文件夹中打开」 |
| 勾选但删除失败 | 标题「已导入 PageRoot」；正文见 §8.4；无自动重试按钮 |

「在文件夹中打开」定位新项目的用户可见根目录，不是原稿目录，也不是 `.pageroot/`。

现行文案「已打开 / 原来的文件没有改动。」在实施后废止，因为它没说文件已经进入项目目录。

## 10. 打开队列与并发

本确认框是打开流程的一部分，仍受主进程项目打开队列和渲染器 FIFO 约束：

- 弹出确认框之前，必须已经按项目切换边界收口当前编辑、评论、附件和项目规则。收口失败则不选文件、不出现确认框，当前项目保持不变。
- 确认框可见时，该外部请求视为「已开始」。更新的外部打开请求可以**替换**待确认文件：确认框改显示新文件名，复选框恢复未勾选，不导入、不删除被替换的那一份。
- 不得在确认框背后导入被替换掉的文件。
- 较慢的旧读取不能在用户已经确认 B 之后再导入 A。
- 无效路径、非 HTML、文件消失：只报告失败，关闭确认框，不改变当前项目。

从文件选择器到确认框之间，用户尚未看到确认框。这一阶段的更新外部请求仍按「尚未开始的旧请求由最新请求取代」处理。

## 11. 状态与权限边界

### 11.1 状态所有权

| 事实 | 唯一 owner | 是否持久 |
|---|---|---|
| 已验证、尚未确认的外部 HTML 路径与请求 ID | 主进程打开队列 / 外部打开 mailbox（与现有外部打开同一类权威） | 仅当前进程内存；close-commit handoff 只保存已验证路径，不保存「已同意导入」或勾选状态 |
| 确认框是否可见、当前勾选、展示用文件名与面包屑 | 渲染器打开/导入确认工作副本，由 `ProjectWorkflow` 编排 | 不持久 |
| 是否已经导入、V1 路径、项目身份 | 现有 `ProjectFileRepository` + Registry | 是 |
| 是否删除原稿 | 主进程在导入成功后执行的一次性特权操作 | 不持久；结果只表现为原路径是否还在 |

不新增浏览器存储，不把勾选写进 `project.json` / Registry / 偏好。

### 11.2 安全

删除原稿会让 PageRoot 第一次在**配置项目根之外**对用户文件做破坏性操作。因此：

- 默认路径（只复制）不扩大删除权限。
- 删除不得成为通用「删除任意本地文件」IPC。
- 路径不能由渲染器指定；只能是本轮主进程已经接受的外部打开/文件选择路径。
- 项目根内路径、V1 工作文件、隐藏快照、软链接逃逸一律失败关闭。
- 失败关闭时原稿仍在，已导入项目仍在。

`importExternal` 继续只在配置项目根内复制和发布。它不负责删除外部原稿。

## 12. 明确不改的合同

- 正式版本只在导入成功时创建版本 1，以及用户采纳 AI 候选时创建下一个整数版本。
- 可见工作文件与界面 ordinal 一致：`…-V1.html`、`…-V2.html`。
- 导入仍不改写 HTML 字节来重定向相对资源。
- 预览仍可把原目录当作会话级资源根；这不是项目权威，也不因为删除原稿而改写 HTML。
- 原稿删除后，该会话级资源根若已不可用，缺失资源只影响预览，不否定已经导入的 V1。

## 13. 失败与恢复

| 情况 | 用户看到 | 磁盘 |
|---|---|---|
| 文件选择器取消 | 无新提示 | 不变 |
| 确认框取消 | 确认框关闭 | 不变 |
| 确认期间文件被改 | 未导入，可重新打开 | 原稿仍在，无新项目 |
| 导入事务失败 | 现有导入失败说明 | 原稿仍在；不留半截项目 |
| 导入成功、未勾选删除 | §9 未删除提示 | 项目已发布；原稿仍在 |
| 导入成功、勾选且删除成功 | §9 废纸篓提示 | 项目已发布；原稿在废纸篓 |
| 导入成功、勾选但删除失败 | §9 删除失败提示 | 项目已发布；原稿仍在原处 |
| 确认中崩溃 | 下次启动回到上一项目或欢迎项目 | 不导入 |
| 导入成功后、删除前崩溃 | 下次打开已导入的 V1 | 项目已在；原稿可能仍在 |

## 14. 验收标准

实施完成时，下列项必须可自动验证或由桌面 Electron 测试给出确定性断言。

- [ ] 打开未登记 HTML 时出现 §4.1 确认框，且在确认前不创建项目、不写 Recent、不把该 HTML 挂到画布。
- [ ] 确认框标题使用真实文件名；V1 文件名与随后磁盘上的可见工作文件完全一致。
- [ ] 默认项目根显示「文稿 › PageRoot › 项目」，不显示具体项目文件夹名。
- [ ] 取消、Escape、点按遮罩都不导入、不删除；当前项目保持不变。
- [ ] 不勾选并导入后，原稿字节与路径不变；当前文件是 `<主干>-V1.html`；Registry 中有新项目。
- [ ] 勾选并导入后，新项目同样完整；原 HTML 进入废纸篓；项目内 V1 仍在。
- [ ] 勾选但删除失败时项目可打开，原稿仍在，提示符合 §8.4。
- [ ] 有效 v4 项目、项目目录入口、启动恢复、欢迎项目首次建立都不出现本确认框。
- [ ] 再次打开未删除的原稿，会再次出现确认框，并在确认后创建**另一个**新项目，而不是回到第一次的项目。
- [ ] 渲染器不能凭自造路径删除项目外文件；缺少本轮请求 ID 或路径越权时失败关闭。
- [ ] 确认框可见时被更新的外部打开请求替换，不导入旧文件，复选框回到未勾选。
- [ ] 采纳后的正式版本仍从 V2 起，文件名不含 `V0`、`V1.1`。
