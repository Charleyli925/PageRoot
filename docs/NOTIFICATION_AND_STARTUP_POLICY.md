# 源页：提示精简与启动行为

## Toast

Toast 只保留三类：阻止当前操作的错误、必须立即决定的警告、发生在后台且当前界面看不到的结果。AI 处理中、复制状态、校验步骤、保存状态和当前版本状态都由原位置或流程看板展示，不再重复弹 Toast。

- 全局 Toast 与画布内“暂时不能直接编辑”统一使用 `NoticeBar`：同一套语义色、图标、玻璃材质、关闭按钮、操作按钮和键盘焦点样式，不再各自维护覆盖样式。
- 全局 NoticeBar 固定在 Canvas 顶部居中，评论栏和项目抽屉不被遮挡；画布内提示固定在当前 Canvas 顶部。持久化的流程问题仍留在原位置，不伪装成短暂 Toast。
- 成功/普通信息：2.5 秒；实际只用于带操作入口的后台结果。
- 必要警告与画布内可恢复提示：5 秒。
- 阻断错误、需用户决定或带显式操作的消息：持续显示，直到关闭或处理。
- 鼠标停留或键盘焦点进入 Toast / 画布内提示时暂停计时，离开后才继续；用户不会在阅读或操作按钮时失去提示。
- 单一 Toast 出口只承载当前最需要处理的事项。新的阻断或决定可以替换旧提示，但旧问题的真实状态必须继续留在对应面板中，不能因 Toast 被关闭或替换而消失。
- 文案：标题说明发生了什么；正文只说明结果和下一步，不展示 IPC、异常类、runtime-state、Hash 等内部词。
- 操作按钮必须同时说明对象或可见结果，例如“重新保存规则”“重新打开此版本”；不得使用脱离正文就没有意义的“重试”“查看”或“处理第一条”。

## 恢复责任

业务流程必须先决定由谁完成下一步，再决定是否显示 NoticeBar：

- `silent-recover`：数据兼容或确定性修复由系统静默完成。
- `defer-and-resume`：短暂状态结束后自动继续用户刚才的操作。
- `direct-action`：系统无法继续，但用户只需执行一个明确动作。
- `user-choice`：存在多个安全选项，必须由用户决定。
- `background-result`：结果发生在后台，当前界面没有其他可见入口。
- `inform-in-place`：在原控件或流程面板更新，不再重复弹全局提示。

只有 `direct-action`、`user-choice` 和必要的 `background-result` 可以进入 Canvas 顶部。持续警告和错误必须提供明确操作按钮；若恢复动作已经在原位置，则 NoticeBar 只能作为能直接定位到该位置的入口。

## 错误闭环

提醒不是流程终点。每个会阻止用户继续的状态，都必须在原位置保留原因与至少一条真实可执行路径：

- 可重试的读取、保存、Finder、附件和差异操作提供对象明确的操作，例如“重新保存规则”或“重新显示此版本”。
- 浏览器打开非 UTF-8 HTML 时，明确说明原文件未修改，并提供“重新选择”；提示不自动消失。
- 空文件、超过 25 MB 或超出 10 个上限的附件必须明确说明哪些没有加入；同批有效附件继续保留。仍有容量时提供“重新选择”，容量已满时提供“查看附件”并引导先移除一个，不能在浏览器预览路径静默返回。
- 画布直接编辑受阻时提供“添加评论”；源码映射无法建立时提供“重新载入”，不能只告诉用户失败原因。
- 项目切换遇到任务准备、画布核对或新修改写入等短暂状态时，保留目标项目并在状态结束后自动继续；当前内容不安全时提供“导出当前编辑”并在问题解决后继续原操作。
- 全局评论按稳定的 `body + module` 语义识别；旧记录缺少运行时 `tagName` 时自动标准化为 `exact`，不得要求用户重新选择“整个页面”。
- 真正失联的局部评论继续保留评论与附件；入口直接打开并高亮具体评论，进入画布重新定位。多条时完成一条自动进入下一条；若恢复流程来自“发送”，全部完成后自动继续原发送操作。
- AI 返回 `error` 或 `no-change` 时解除画布锁定，在处理面板提供“返回编辑”和“调整要求后重试”。
- Request 发送结果未知时保持 fail-closed，但提供“重新核对任务状态”和“重新打开源页”；不能留下一个永久禁用的取消按钮。
- `PROJECT.md` 读取失败时不显示伪造的可编辑正文，也不把错误文案标成“已保存”；原位置提供“重试读取”和“返回项目”。

所有 Renderer → Bridge 请求都有超时边界。普通读写 15 秒，附件 30 秒，建立 AI Request 60 秒；超时后必须释放按钮忙碌态，并进入上述可恢复路径。Bridge 意外停止时，当前窗口内容保持可导出，Renderer 与原生对话框都提供“返回源页处理 / 重新打开源页”。重新打开前仍执行关闭写入检查，未安全写入时要求先导出或处理，不能直接丢弃内存内容。

## 首次启动

仅启动 App、打开“项目”面板或浏览最近文件不创建空的项目记录目录。用户第一次真正编辑、添加附件/评论、发送 AI Request，或明确展开“项目资料”时，才创建：

`~/Documents/PageRoot/项目记录`

若已有目录，选择顺序是 PageRoot → YuanYe → HTML AI 工作台，以兼容旧数据。

## 再次启动

应用尝试恢复上次当前 HTML 和它的运行态。若上次文件存在，恢复当前项目、评论、编辑状态、AI 处理状态或“最新版可打开”状态；若文件移动、删除、无权限或内容损坏，明确显示原因，并提供“选择其他 HTML”，不会静默回到欢迎页假装恢复成功。
