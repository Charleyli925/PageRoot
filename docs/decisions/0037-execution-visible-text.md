# 0037 执行轮次的可见文本与过程消息

- 状态：Accepted
- 日期：2026-08-23
- 取代：ADR 0036 中「执行模式文本预算为 0」这一条（讨论模式的边界不变）

## 背景

ADR 0036 只为讨论轮次放行 Agent 的可见文本，执行轮次的预算定为 0。当时的理由是：执行
轮次的产出物是 HTML 候选，Agent 的散文不是产出物，放进界面等于把不可信文本当成结论。

真机走查推翻了这个判断的一半。执行期间用户在界面上**只能看到右上角一个按钮换了文案**，
其余区域压暗不动；一份四行的静态阶段清单也无法回答"它现在在做什么、卡住了没有"。用户
的原话是"其他地方灰着不动，也很奇怪，用户不知道在发生啥"。

不透明本身就是一种风险：分不清"在跑"与"挂了"的用户，会去重复发送，而重复发送正是
`AGENT_RETRY_OUTPUT_PRESENT` 这类 fail-closed 拒绝的来源。

## 决定

执行轮次放行**与讨论轮次同一套、同一预算**的可见文本，并把阶段变化表达为对话中的过程
消息。三条边界与 ADR 0036 完全一致，不放宽：

1. 只采 `agent_message_chunk` 的文本。`agent_thought_chunk` 与任何非文本块一律丢弃，
   隐藏推理不进产品界面。
2. 预算 64 KiB，按字符边界截断并标记 truncated。控制字符剔除。
3. 文本是**叙述**，永远不是结论：它不影响候选的接受与否，不参与任何校验，不能改变
   Hash、路径或版本判定。候选的权威仍然只来自完整 HTML 检查与版本连续性检查。

新增两条执行轮次特有的约束：

4. 过程消息由 PageRoot 依据 run 的**持久状态**生成，不由 Agent 自称的进度决定。Agent
   的文本只作为该阶段的附注呈现，不能声称阶段已完成。
5. 思考流默认展开但**可一键收起**，且收起状态是用户偏好而非每轮重置。界面必须在不展开
   任何文本的情况下依然能说清当前阶段。

## 后果

- 用户能看见"在做什么"，因此更少发生因误判卡死而重复发送。
- 执行轮次的 Agent 文本与讨论轮次共用同一条采集与消毒路径，没有第二套实现。
- 不可信文本的暴露面确实扩大了一档：原先执行轮次为 0，现在与讨论轮次相同。这被接受，
  因为放行的是同一类内容、同一套消毒、同一个预算，且它对候选判定零权重。
- ADR 0036 的其余条款继续有效；讨论轮次的行为不变。

## 不在本决定内

- 不放行 `agent_thought_chunk`。用户要的是"看得见过程"，而不是模型的内心独白。
- 不因文本内容改变任何 fail-closed 判定。
- 不把过程消息写入 Conversation 的持久消息流；它们随轮次结束而消失，落盘的仍然只有
  讨论轮次密封的问答。
