# 源页提醒消息全量台账

> 行为基线：`fix/notification-recovery-flow` 分支当前实现。
>
> 统计日期：2026-07-26。
>
> 目的：让产品、设计、开发和测试都能回答四个问题——为什么发生、为什么要提醒、用户该做什么、系统为什么不能自己处理。

## 1. 先说结论

源页目前不是“发生错误就弹提醒”，而是先判断下一步归谁负责：

1. 系统能安全处理：自动处理，不提醒。
2. 当前控件或面板能解释：留在原位置，不弹全局提醒。
3. 用户必须改变一个外部条件：显示全局操作提醒。
4. 用户必须在多个安全结果中作决定：显示全局选择提醒或原位决策面板。
5. 结果发生在后台项目，当前页面没有其他可见入口：显示后台结果提醒。
6. 操作会舍弃内容、替换当前 HTML 或覆盖关键选择：使用确认弹窗。
7. Renderer 尚不可用或应用无法安全关闭：才使用 macOS 原生提示。

最重要的判断不是“错误严不严重”，而是“用户现在是否真的需要做事”。错误级别、红色样式、`sticky` 或按钮本身，都不能自动获得打扰用户的资格。

## 2. 统计口径

### 2.1 本文包含什么

- Canvas 顶部的全局 `NoticeBar`。
- Canvas 内部的编辑受阻 `NoticeBar`。
- 评论栏、项目抽屉、AI 处理面板里的原位提醒与决策。
- 浏览器确认弹窗。
- Electron/macOS 原生提示。
- 保存、锁定、剪贴板和 AI 流程等持续状态。
- 代码中仍保留、但会被当前策略过滤而不显示的消息定义。
- 系统自动恢复、因此正常情况下不显示消息的场景。

### 2.2 本文不包含什么

- 普通按钮名称、输入框帮助文字和空状态，除非它们承担恢复或状态说明。
- 文件选择器、保存位置选择器本身；它们是用户主动打开的系统工具，不是提醒。
- 开发环境错误浮层、控制台日志、IPC 原始错误和测试框架输出；它们不是正式产品界面。
- 操作系统、GitHub、QoderWork 或其他外部产品自行显示的消息。

### 2.3 当前静态统计

| 项目 | 数量 | 如何理解 |
| --- | ---: | --- |
| `setToast(...)` 调用点 | 38 | 包括创建消息、复用帮助函数和清除消息 |
| 仅用于清除当前消息 | 6 | `setToast(null)`，不产生用户可见内容 |
| 其余消息调用点 | 32 | 包括全局消息与会被策略留在原位的定义 |
| `direct-action` | 6 | 用户必须改变条件才能继续 |
| `user-choice` | 2 | 用户必须作安全选择 |
| `background-result` | 11 个固定 + 1 个动态 | 仅在当前界面没有结果入口时显示 |
| 未声明 disposition | 13 | 归为 `inform-in-place`，当前策略不弹出 |
| 动态 disposition | 1 | 根据评论是否仍打开，在操作提醒与后台结果间切换 |
| Canvas 编辑提示 | 统一入口，按真实失败原因变体 | 支持的多行粘贴与 Enter 不触发；无法精确写回时才说明 |
| 浏览器确认弹窗 | 1 | 仅在重新载入会舍弃尚未写回的桌面编辑时出现 |
| 浏览器只读预览 | 1 条持续状态 | 正式能力；不能编辑、评论、附加文件或发送 AI |

本文保留原有编号，方便审阅前后变化；标注“已取消提醒”的条目是决策记录，不代表代码仍会弹出消息。

## 3. 消息出口与样式

### 3.1 全局 NoticeBar

出现位置：应用视口顶部导航下方、Canvas 可视区域中央；使用
viewport-fixed 定位，不随 HTML 页面滚动，不遮挡右侧评论栏。

当前视觉参数：

- 最大宽度 `520px`，窄屏时左右至少保留 `12px`。
- 最小高度 `68px`，圆角 `15px`。
- 白色半透明渐变背景，`22px` 背景模糊，带轻微饱和度和内高光。
- 标题 `13px`，正文 `12px`，操作按钮 `11.5px`。
- 图标区域 `32 × 32px`，操作按钮和关闭按钮最小高度 `32px`。
- 成功为绿色，普通信息为紫色，警告为金棕色，错误为红色。
- 进入动画约 `160–200ms`；用户启用“减少动态效果”时取消动画。
- 鼠标悬停或键盘焦点进入后暂停自动消失。
- 统一使用 `role="status"`、`aria-live="polite"` 和 `aria-atomic="true"`，不抢断屏幕阅读器正在播报的主流程。

显示时长：

- `direct-action`、`user-choice`、错误或 `sticky`：持续显示，直到用户处理或关闭。
- `background-result`：通常 7 秒；若本身是错误或 `sticky`，则持续显示。
- 普通警告理论值为 5 秒、普通成功/信息为 2.5 秒，但未显式准入的消息不会进入全局 NoticeBar。

### 3.2 Canvas 内编辑提示

与全局 NoticeBar 使用同一组件和视觉语言，并提升到应用视口固定层。
普通编辑受阻提示 5 秒后自动消失；源码映射完全失败时持续显示。它
不会因用户滚动到页面下方而藏在文档顶部，也不会遮挡项目抽屉或改变
当前文字位置。

### 3.3 原位提醒与流程面板

适用于“问题属于哪个控件，就在哪里解释”的场景，例如：

- 评论记录失败：留在评论栏。
- `PROJECT.md` 保存失败：留在规则编辑器下方。
- AI 状态核对：留在本轮处理面板。
- 外部文件冲突：留在 Canvas 上方的持久横幅。

原位提醒没有统一倒计时。只要真实问题还存在，它就保留；问题解除后随状态一起消失。

### 3.4 确认弹窗

只用于“继续会产生明确不可逆或易误解结果”的操作。按钮必须对应两个真实结果，不能把普通错误包装成确认弹窗。

### 3.5 macOS 原生提示

只在 Web Renderer 不能承担恢复、应用关闭/重启涉及本地写入边界，或者应用根本无法启动时使用。同一问题不会同时显示 Renderer 横幅和原生弹窗。

## 4. 系统如何决定是否提醒

```text
发生异常或状态变化
  ├─ 能否安全自动恢复？
  │    └─ 能：自动重试、回读或继续核对，不提醒
  ├─ 当前控件/面板是否已经能说明？
  │    └─ 能：原位显示，不弹全局提醒
  ├─ 用户是否必须改变一个条件？
  │    └─ 是：direct-action
  ├─ 用户是否必须从多个安全结果中选择？
  │    └─ 是：user-choice / 原位决策面板
  ├─ 是否是其他项目的后台结果？
  │    └─ 是：background-result
  ├─ 继续是否会舍弃或替换内容？
  │    └─ 是：确认弹窗
  └─ Renderer 是否不可用？
       └─ 是：macOS 原生提示
```

## 5. 自动处理、正常不提醒的场景

### A01. 一次性的读取失败

- 用户刚做了什么：打开附件、在 Finder 显示文件，或系统读取状态。
- 系统发现什么：第一次读取遇到超时、临时连接失败或可重试状态码。
- 系统怎么做：GET/HEAD 请求自动再试一次，间隔约 `180ms`。
- 用户要做什么：什么都不用做。
- 为什么不提醒：一次瞬时失败没有形成用户问题，弹出消息只会制造噪音。
- 小白案例：像网页偶尔“卡了一下”，系统自己再读一次就成功，不需要你点“重试”。

### A02. AI 状态轮询偶发失败

- 用户刚做了什么：已经发送一轮要求，正在等待 AI 返回。
- 系统发现什么：某一次状态查询没有响应。
- 系统怎么做：下一轮继续自动查询，不累计次数，也不把暂时失败升级成用户提醒。
- 用户要做什么：无需操作。
- 为什么不提醒：AI 任务可能仍在正常运行，单次轮询失败不等于任务失败。
- 小白案例：快递查询页面一瞬间没刷新，并不代表包裹丢了。

### A03. Request 提交结果未知

- 用户刚做了什么：点击“发送至 Qoder”。
- 系统发现什么：请求可能已经建立，但客户端没有收到明确答复。
- 系统怎么做：画布保持只读，后台读取权威工作区状态；不重复发送同一轮要求。
- 用户要做什么：等待自动核对。只有工作区本身明确不可用时，才从工作区横幅导出或重新打开源页。
- 为什么不直接重试提交：原样重试可能建立两份重复任务。
- 小白案例：付款页面转圈时，先查订单是否已经生成，不能再次扣款。

### A04. `PROJECT.md` 自动保存与写入结果未知

- 用户刚做了什么：修改项目规则后停下输入、关闭规则页或切换项目。
- 系统发现什么：写入请求报错或超时，无法仅凭响应判断是否已成功。
- 系统怎么做：停输约 700ms 后自动保存；结果未知时重新读取 `PROJECT.md`，内容已经一致就直接视为成功。
- 用户要做什么：通常无需操作；只有回读后仍不一致，才在原编辑器点“再次保存”。
- 为什么不弹全局提醒：保存由系统负责，错误也有明确的原位入口。
- 小白案例：记事本自动保存时网络闪断，系统先核对文件，已经写进去就不再吓你。

### A05. 旧版全局评论缺少运行时字段

- 用户刚做了什么：打开旧项目或发送旧评论。
- 系统发现什么：评论没有 `tagName`，但稳定的 `body + module` 身份仍能证明它是整个页面。
- 系统怎么做：自动标准化为可用目标。
- 用户要做什么：什么都不用做。
- 为什么不提醒：这是已知数据兼容问题，系统有确定答案，不应把迁移工作交给用户。
- 小白案例：旧通讯录没存“国家”字段，但号码格式足以确定是中国号码，系统自动补全。

### A06. 已有一条未保存评论

- 用户刚做了什么：准备在另一个位置写评论，但已有一条未发送草稿。
- 系统发现什么：草稿仍完整存在。
- 系统怎么做：保留原草稿和附件，阻止建立第二条草稿或发送本轮要求，并显示“上一条评论还未保存”。
- 用户要做什么：点击“继续填写”，再点击“评论”保存；保存后仍可修改，然后继续添加下一条。
- 为什么不自动保存或允许多条草稿：点击“评论”是用户确认这条要求进入本轮的明确边界；单一未保存状态更容易理解，也避免发送前再管理一组半成品。
- 小白案例：填写一条待办时，先确认保存当前内容，再新建下一条；保存不等于已经发送给 AI。

### A07. 项目切换遇到短暂流程占用

- 用户刚做了什么：AI 提交、附件上传、规则保存、画布核对或自动保存过程中选择另一个项目。
- 系统发现什么：当前操作还未结束，但没有需要用户决定的问题。
- 系统怎么做：记住目标项目；操作结束后自动打开。
- 用户要做什么：等待当前步骤完成。
- 为什么不弹提示：下一步仍由系统负责，用户没有新的动作。
- 小白案例：电梯门正在关闭，你按了下一层，系统记住指令，门关好后自动运行。

### A08. 评论数量超过 100

- 用户刚做了什么：继续添加大量评论。
- 系统发现什么：评论数量很多。
- 系统怎么做：保留全部评论；超过 40 条后使用虚拟化渲染。
- 用户要做什么：照常工作。
- 为什么不提醒或阻止：条数本身不是错误，性能问题由渲染策略解决。
- 小白案例：通讯录有 101 个联系人不该弹警告，只需要列表滚动仍然顺畅。

## 6. 全局 NoticeBar：附件与评论

### G01. 附件选择期间关闭评论（已取消提醒）

- 用户触发：在选择或上传附件期间尝试关闭评论、切换项目或关闭应用。
- 系统条件：附件归档仍在进行。
- 当前行为：评论关闭按钮、项目切换和关闭流程会等待上传完成；完成后附件仍归属原评论或草稿。
- 用户操作：无需重新选择，也不会看到“附件没有加入”。
- 为什么不提醒：这是系统能够确定完成顺序的并发问题，不应让用户重复上传。
- 小白案例：照片仍在上传时，相册先把“离开”动作排队；上传完成后自动继续，而不是让你重新选照片。

### G02. 附件全部不符合要求

- 用户触发：一次选择了空文件、超过 25MB 的文件，或在已满 10 个附件时继续选择。
- 系统条件：本批次没有任何文件可以安全加入。
- 当前文案：标题“附件没有加入”；正文按实际情况组合，例如“已达到每条评论 10 个附件的上限，1 个未加入。请先移除一个附件，再重新选择。”
- 操作按钮：容量已满时“查看附件”；仍有容量时“重新选择”。
- 样式与时长：警告色、持久、`direct-action`。
- 用户操作：移除一个附件，或选择符合大小和内容要求的文件。
- 为什么提醒：失败条件只有用户能改变。
- 为什么不自动删除旧附件：系统不知道哪个旧附件更不重要。
- 小白案例：行李箱已经装满，系统可以告诉你超重，但不能替你扔掉一件衣服。

### G03. 部分附件没有加入

- 用户触发：一批文件中有些有效、有些为空、过大或超过数量上限。
- 系统条件：有效附件已保存，其他附件被拒绝。
- 当前文案：标题“部分附件没有加入”；正文列出失败原因，并明确“已加入的附件仍然保留”。
- 操作按钮：按剩余容量显示“查看附件”或“重新选择”。
- 样式与时长：警告或错误色；评论仍打开时持续显示。
- 用户操作：检查已加入列表，只补充缺少的文件。
- 为什么提醒：静默丢弃会让用户误以为整批都成功。
- 为什么不整批回滚：保留有效文件能减少重复操作。
- 小白案例：上传 10 张照片时 9 张成功、1 张过大，系统保留 9 张，只告诉你处理最后一张。

### G04. 浏览器只读预览中添加附件（入口已取消）

- 用户触发：使用纯浏览器预览。
- 系统条件：浏览器预览没有本地项目记录，并且产品边界明确为只读。
- 当前行为：编辑、评论、附件与“发送至 Qoder”入口都不可用；顶部持续说明“浏览器预览 · 只读”“操作不会保存”。
- 用户操作：只需浏览和试用页面自身交互；需要修改时在桌面版打开本地 HTML。
- 为什么不弹提醒：不可用能力在入口处已经被禁用，不应等用户点击后再报错。
- 小白案例：展厅里的样机可以观看和试按，但没有“保存订单”按钮，也不会等你按完才说不能保存。

### G05. 添加附件时，项目资料没有建立成功

- 用户触发：选择附件。
- 系统条件：源页无法建立当前项目的受控记录目录。
- 当前文案：标题“附件尚未加入”；正文默认“项目资料暂时无法建立；附件没有丢失，请重试选择。”
- 操作按钮：“重新选择”。
- 样式与时长：警告色、`direct-action`。
- 用户操作：确认本地项目服务恢复后重新选择附件。
- 为什么提醒：附件没有进入受控副本，不能假装成功。
- 小白案例：文件柜没有创建成功，原文件还在你手里，但需要等文件柜可用后重新归档。

### G06. 图片暂时无法预览

- 用户触发：点击图片缩略图。
- 系统条件：自动读取一次重试后仍失败。
- 当前文案：标题“图片暂时无法预览”；正文默认“附件仍保留在评论中，可以重新读取。”
- 样式与时长：警告色、`background-result`、7 秒。
- 用户操作：稍后从原缩略图再次打开。
- 为什么提醒：点击没有产生预期结果，但附件并未丢失。
- 为什么没有额外“重试”按钮：缩略图本身就是原入口。
- 小白案例：照片一时打不开，但照片仍在相册里；不需要再弹一个与照片相同功能的按钮。

### G07. 普通附件暂时无法打开

- 用户触发：点击文件附件。
- 系统条件：自动读取一次重试后仍失败。
- 当前文案：标题“附件暂时无法打开”；正文默认“附件仍保留在评论中，可以重新下载。”
- 样式与时长：警告色、`background-result`、7 秒。
- 用户操作：稍后从原附件条再次打开。
- 为什么提醒：用户需要知道点击没有成功，也需要知道文件仍安全。
- 小白案例：下载按钮没反应时，告诉你文件还在即可，不需要再造一个“重新下载”弹窗按钮。

### G08. 一条或多条评论目标需要重新定位

- 用户触发：打开旧项目、页面结构变化后编辑评论，或发送本轮要求。
- 系统条件：评论目标已经不存在或存在多个候选，不能唯一证明位置。
- 当前文案：
  - 单条：“1 条评论需要重新定位”“请选择这条评论的新位置，评论和附件已保留。”
  - 多条：“N 条评论需要重新定位”“将从第 1 条开始，完成后自动进入下一条。”
- 操作按钮：单条“选择新位置”；多条“开始重新定位”。
- 样式与时长：警告色、持久、`user-choice`。
- 用户操作：在 Canvas 重新选择目标；多条时完成一条会自动进入下一条。
- 后续流程：若提醒来自“发送”，全部定位完成后自动继续原发送意图。
- 为什么提醒：系统没有唯一答案，猜错位置会把要求交给错误内容。
- 小白案例：快递地址只剩“人民路”，城市已经丢失，系统必须让你重新确认，不能随便选一个人民路。

### G09. 当前草稿目标无法安全定位

- 用户触发：正在填写评论时页面内容变化。
- 系统条件：草稿所指位置失去唯一性。
- 当前文案：标题“评论目标无法安全定位”；正文“评论内容和附件仍保留；重新选择画布位置后即可继续。”
- 操作按钮：“重新选择目标”。
- 样式与时长：警告色、`user-choice`。
- 用户操作：重新点选 Canvas 位置。
- 为什么提醒：文字和附件可以保留，但目标不能由系统猜测。
- 小白案例：便签内容还在，但原来贴的那一行文字已经被改掉，需要你重新贴到正确位置。

### G10. 已有评论目标不存在或存在多个候选

- 用户触发：点击、编辑或发送一条已有评论。
- 系统条件：目标解析为 `orphaned` 或 `ambiguous`。
- 当前文案：标题按情况为“原目标已不存在”或“目标存在多个候选”；正文“评论和附件仍保留；重新选择画布位置即可继续。”
- 操作按钮：“重新选择目标”。
- 样式与时长：警告色、`user-choice`。
- 用户操作：为该评论重新选择位置。
- 为什么提醒：这是内容归属决定，不是技术重试。
- 小白案例：文档里出现了两个相同标题，系统不知道评论指哪一个，只能请你点明。

## 7. 全局 NoticeBar：项目、文件与导出

### G11. 切换项目时，项目规则尚未保存（改为自动保存）

- 用户触发：修改 `PROJECT.md` 后打开另一个项目。
- 系统条件：规则编辑器内容与磁盘内容不同。
- 当前行为：系统先自动保存并回读核对；成功后直接打开目标项目。只有确认保存失败时，规则编辑器原位显示“再次保存”。
- 用户操作：正常情况下无需操作，也不会看到全局提醒。
- 为什么不再让用户选择保存或放弃：用户已经通过编辑表达了保留意图；默认保存是可逆且符合主流程的动作，“还原修改”仍留在规则页。
- 小白案例：云文档切换页面前先自动保存，不会每次都问“要不要保存”。

### G12. 切换项目时，当前 HTML 正在写入（改为延后并自动继续）

- 用户触发：自动保存或画布核对过程中切换项目。
- 系统条件：当前写入还没有得到确定结果。
- 当前行为：系统记住目标项目，完成写入与回读核对后自动继续；不弹“当前 HTML 还没有更新成功”。
- 用户操作：无需再次点击目标项目。只有写入最终进入持久冲突或失败横幅时，才从横幅导出当前编辑或重新载入。
- 为什么不提醒：短暂的“正在写”不是失败，用户此时没有额外动作。
- 小白案例：文件正在复制时，系统排队执行“打开下一项”，不要求你反复点。

### G13. 切换项目时，评论正在记录（改为延后并自动继续）

- 用户触发：评论持久化或附件上传过程中切换项目。
- 系统条件：当前记录尚未完成。
- 当前行为：系统保留目标项目，等待评论记录和附件归档完成后自动继续；评论草稿也同步保存在本地恢复记录中。
- 用户操作：无需手动“重试记录评论”。若服务最终确认不可用，评论栏原位保留错误和重试入口。
- 为什么不提醒：只要系统仍能完成当前写入，就不应把内部时序变成用户任务。
- 小白案例：聊天附件还在上传时切换会话，应用先传完再离开，不让你重新操作。

### G14. 无法打开选中的 HTML

- 用户触发：从文件选择器或最近打开列表打开 HTML。
- 系统条件：文件移动、删除、损坏、无权限或暂时不可读。
- 当前文案：标题“无法打开这个 HTML”；正文按来源说明“文件可能已移动……”。
- 操作按钮：最近记录为“重新选择位置”，普通打开为“重新选择”。
- 样式与时长：错误色、持久、`direct-action`。
- 用户操作：选择文件的新位置，或从最近打开列表移除旧记录。
- 为什么提醒：系统无法知道文件搬到了哪里。
- 小白案例：桌面快捷方式指向的文件被移动，需要你告诉应用新地址。

### G15. 文件编码或类型不支持

- 用户触发：在浏览器预览路径选择文件。
- 系统条件：文件不是 `.html/.htm`，或不是 UTF-8。
- 当前文案：
  - 编码问题：“文件编码不支持”“原文件没有被修改。请先转换为 UTF-8，再重新选择。”
  - 类型问题：“文件无法打开”“请选择 .html 或 .htm 文件后重试。”
- 操作按钮：“重新选择”。
- 样式与时长：警告色、持久、`direct-action`。
- 用户操作：转换编码或选择正确文件。
- 为什么提醒：自动转码可能改变原文件字节，违背源码保真。
- 小白案例：应用只接受指定格式，不能为了“帮忙”就擅自改写原文件。

### G16. 无法在 Finder 中显示当前源 HTML

- 用户触发：点击当前项目的“Finder”。
- 系统条件：自动尝试后仍无法显示，文件可能已移动。
- 当前文案：标题“无法在 Finder 中显示”；正文默认“源 HTML 可能已移动；当前项目仍保持打开，可以重试。”
- 样式与时长：警告色、`background-result`、7 秒。
- 用户操作：稍后从原 Finder 按钮再次尝试。
- 为什么提醒：当前项目仍可用，问题只影响辅助查看。
- 小白案例：文件还在应用里打开，只是“在文件夹中显示”没有成功，不应阻断编辑。

### G17. 项目记录目录暂时无法打开

- 用户触发：点击打开项目记录目录。
- 系统条件：自动尝试后 Finder 仍未打开。
- 当前文案：标题“项目记录暂时无法打开”；正文“项目记录仍保留在本地，可以重新尝试。”
- 样式与时长：警告色、`background-result`、7 秒。
- 用户操作：稍后从原入口再次打开。
- 为什么提醒：只是辅助导航失败，不代表记录丢失。
- 小白案例：文件柜抽屉暂时拉不开，但柜内文件并没有消失。

### G18. HTML 副本没有导出

- 用户触发：点击“导出 HTML 副本”并选择位置。
- 系统条件：写入失败、目标位置不可用，或需要重新选位置。
- 当前文案：标题“副本没有导出”；正文保留具体原因，并明确“当前源 HTML 没有被改动。”
- 操作按钮：“重新选择位置”。
- 样式与时长：错误色、持久、`direct-action`。
- 用户操作：选择其他文件夹或文件名。
- 为什么提醒：导出是用户明确期待的结果，失败后必须给可改变条件的路径。
- 小白案例：打印机没纸时，需要换纸，而不是反复按同一个打印按钮。

### G19. 重新载入外部文件失败

- 用户触发：点击重新载入磁盘内容。
- 系统条件：安全读取自动重试后仍失败。
- 当前文案：标题“重新载入失败”；正文默认“请稍后重试，源文件没有被覆盖。”
- 样式与时长：错误色、`background-result`；错误消息不会自动消失。
- 用户操作：回到原横幅或原入口，确认文件存在后再次载入。
- 为什么提醒：用户刚发起明确读取，但不能把另一个“重新载入”按钮叠在提醒里。
- 小白案例：刷新失败时告诉你页面没变即可，刷新按钮本身仍在那里。

### G20. 外部差异按钮（已取消）

- 原问题：冲突横幅提供“查看差异”，读取失败后又提示用户重试同一动作。
- 当前行为：冲突横幅只保留真正改变结果的路径——导出当前编辑、重新载入外部文件；不再提供临时差异读取与对应失败提醒。
- 为什么取消：辅助比较不是解除冲突的必要条件，额外入口制造了新的失败分支。
- 小白案例：真正需要决定的是保留哪份文件；打不开一张临时对照图，不应再形成一层错误流程。

### G21. AI 冲突比较按钮（已取消）

- 原问题：AI 冲突面板提供“比较两份内容”，比较失败后只能要求用户再次比较。
- 当前行为：面板直接说明两份内容都已保留，并提供“采用 AI 候选”与“保留外部内容”两个真实结果。
- 为什么取消：它不是恢复动作，且失败只会形成循环；候选文件仍可从受控记录中审计。
- 小白案例：系统把两份合同都保存好，并直接问你最终采用哪份，不再额外依赖一个可能打不开的比较弹窗。

## 8. 全局 NoticeBar：AI 提交、后台结果与历史版本

### G22. 项目记录尚未建立，不能发送

- 用户触发：点击“发送至 Qoder”。
- 系统条件：提交前无法建立或核对项目记录。
- 当前文案：标题“项目记录尚未建立”；正文默认“请确认源 HTML 没有被外部修改后重试。”
- 操作按钮：“重新建立并发送”。
- 样式与时长：警告色、持久、`direct-action`。
- 用户操作：确认源文件状态后重新建立。
- 为什么提醒：Request 必须归属确定项目，不能在身份未知时发送。
- 小白案例：寄件前必须先生成正确运单，不能把包裹交给一个没有地址的订单。

### G23. 本轮 Request 明确没有提交（改为处理面板结果）

- 用户触发：点击“发送至 Qoder”。
- 系统条件：明确确认 Request 未建立；这与“结果未知”不同。
- 当前行为：画布恢复编辑，本轮处理面板显示“本轮没有改动当前 HTML”和具体原因；底部提供“返回编辑”“调整要求后重试”。
- 用户操作：在同一个流程面板查看原因并决定是否修改要求；不再弹全局“本轮没有提交”。
- 为什么改为原位：错误与本轮要求、冻结内容和处理步骤需要一起阅读。
- 小白案例：银行明确显示“转账未发起”时可以重试；若只是不知道结果，则必须先查流水。

### G24. 其他项目的新版本已生成

- 用户触发：在一个项目等待 AI 后切换到了另一个项目。
- 系统条件：后台项目生成并安全提交了候选版本。
- 当前反馈：最近项目列表标记“新版本可查看”；必要时最多显示一条短成功消息和“打开项目”。完成后临时输出异常仍在项目记录中说明。
- 用户操作：需要时切回对应项目。
- 为什么只保留一次轻提示：列表已经是持续状态来源，全局消息只承担后台刚完成的即时反馈。
- 小白案例：后台下载完成时需要告诉你，但不应把你强制切回下载页面。

### G25. 其他项目的新版本可以打开

- 用户触发：在别的项目工作时，后台 AI 完成校验。
- 系统条件：候选版本已安全保留，等待用户打开。
- 当前反馈：最近项目列表标记“新版本可查看”；若刚刚完成，可短暂显示“版本 N 可以打开了”和“打开项目”。
- 用户操作：选择是否切回。
- 为什么提醒：结果完成，但不替用户中断当前工作或自动替换画布。
- 小白案例：另一个下载任务完成，只给通知，不抢走当前窗口。

### G26. 其他项目没有生成新版本（不弹全局消息）

- 用户触发：后台项目的 AI 返回 `no-change`。
- 系统条件：没有可采用的内容变化。
- 当前反馈：最近项目列表标记“已完成 · 无变化”。
- 用户操作：不需要处理；若仍想修改，再切回调整评论。
- 为什么不提醒：这是正常完成结果，持续列表状态已经足够。
- 小白案例：后台任务完成但发现无需更新，告知结果即可。

### G27. 其他项目处理失败（改为项目状态）

- 用户触发：后台项目的 AI 返回错误。
- 系统条件：硬校验、协议或处理失败，源 HTML 未覆盖。
- 当前反馈：最近项目列表标记“需要处理”；完整原因保留在该项目的本轮处理面板。
- 用户操作：方便时切回项目查看。
- 为什么不弹全局错误：最近项目列表提供持久入口，不应在用户处理当前项目时抢占流程。
- 小白案例：后台备份失败需要通知，但不应立刻关闭你正在编辑的文档。

### G28. 其他项目需要处理冲突（改为项目状态）

- 用户触发：后台 AI 完成时，源文件也被外部修改。
- 系统条件：AI 候选与外部 HTML 都有效，不能静默覆盖。
- 当前反馈：最近项目列表标记“需要处理”；切回项目后，冲突面板说明两份内容都已保留。
- 用户操作：切回项目比较并选择。
- 为什么不弹全局错误：选择属于对应项目；持续项目状态比跨项目弹窗更稳定。
- 小白案例：云盘发现本地版和云端版同时修改，必须让你选，而不是随机覆盖。

### G29. 本轮文件无法在 Finder 中显示

- 用户触发：在 AI 处理面板点击“在 Finder 中查看本轮文件”。
- 系统条件：自动尝试后仍无法显示。
- 当前文案：“本轮文件暂时无法打开”“本轮任务仍在处理面板中，可以重新尝试。”
- 样式与时长：警告色、`background-result`、7 秒。
- 用户操作：从原面板再次尝试。
- 为什么提醒：任务本身不受影响，只是辅助入口失败。
- 小白案例：订单详情还在应用里，只是“打开所在文件夹”没有成功。

### G30. 历史版本无法在 Finder 中显示

- 用户触发：点击历史版本的 Finder 入口。
- 系统条件：自动尝试后仍无法显示版本文件。
- 当前文案：“历史版本暂时无法在 Finder 中显示”“请确认项目记录仍然完整后重试。”
- 样式与时长：警告色、`background-result`、7 秒。
- 用户操作：从原历史卡片再次尝试。
- 为什么提醒：不影响当前 HTML，也不需要创建额外重试按钮。
- 小白案例：相册里的老照片还在应用中，只是无法打开所在文件夹。

### G31. 无法打开某个历史版本

- 用户触发：点击历史版本卡片。
- 系统条件：自动读取后仍失败。
- 当前文案：“无法打开这个历史版本”“历史版本没有打开；原来的画布仍保持不变。”
- 样式与时长：错误色、`background-result`；错误不会自动消失。
- 用户操作：检查项目记录后从原卡片再次打开。
- 为什么提醒：明确说明失败没有影响当前画布。
- 小白案例：相册里的某张旧照片打不开，但当前正在看的照片没有被换掉。

### G32. 无法返回当前 HTML

- 用户触发：从历史浏览点击“返回当前 HTML”。
- 系统条件：当前文件读取失败。
- 当前文案：“无法返回当前 HTML”“当前画布仍停留在原来的历史版本；源文件没有被改动。”
- 样式与时长：错误色、`background-result`。
- 用户操作：确认源文件存在后，从原入口再次返回。
- 为什么提醒：用户需要知道自己仍在历史只读视图，不能误以为回到了当前文件。
- 小白案例：退出旧版本预览失败，系统要明确你还在旧版本，而不是假装已经切换。

### G33. 用历史内容替换当前 HTML（能力已取消）

- 原问题：历史卡片既承担只读审阅，又提供回写当前 HTML，产生确认、写入、回读与失败恢复等整套分支。
- 当前行为：历史版本只读查看；可以回到当前 HTML 或在 Finder 中定位历史文件，不提供“设为当前 HTML”。
- 为什么取消：历史审阅的主目标是追溯，不应顺手变成覆盖当前源码的高风险入口。
- 小白案例：档案室允许查看旧合同，但不会在查看按钮旁放一个“覆盖当前合同”。

## 9. Canvas 内编辑提示

以下提示只出现在用户正在编辑的 Canvas 内，不占用全局消息出口。

### C01. 页面暂时不能建立源码映射

- 用户触发：打开 HTML 或重新载入页面。
- 系统条件：源码索引无法建立，不能证明视觉文字与源码位置一一对应。
- 当前文案：标题“暂时不能直接编辑这个页面”；正文“页面仍可正常浏览。请重新载入后再试，或添加评论说明要改什么。”
- 操作按钮：“重新载入”或“重新选择”，取决于是否已经绑定本地源文件。
- 样式与时长：错误色、持续显示。
- 用户操作：重新载入；仍失败时改用评论描述需求。
- 为什么提醒：继续直接编辑可能修改错误源码位置。
- 小白案例：地图定位系统失效时可以继续看地图，但不能假装知道你点击的是哪条街。

### C02. 默认的直接编辑受阻

- 用户触发：双击、输入、删除、粘贴、调整样式或排序。
- 系统条件：底层 Source Patch 无法安全应用，但没有命中更具体的原因。
- 当前文案：标题“这处内容暂时不能直接编辑”；正文“页面内容没有改变。你仍可以选择文字，或添加评论说明要怎么改。”
- 操作按钮：“添加评论”。
- 样式与时长：警告色，5 秒。
- 用户操作：重新选中文字，或用评论交给 AI。
- 为什么提醒：本次直接编辑已停止，需要提供一条不破坏源码的替代路径。
- 小白案例：剪刀无法精确剪到指定线时，先停下并重新对齐，而不是继续乱剪。

### C03. 光标位于两种样式边界

- 用户触发：在两段样式交界处直接输入。
- 系统条件：无法可靠判断新文字属于左侧还是右侧样式。
- 当前文案：标题“请把光标移入文字内部”；正文说明这里是两种文字样式的边界。
- 操作按钮：“添加评论”。
- 用户操作：把光标移到样式内一个字的位置后输入，或添加评论。
- 为什么提醒：自动选择一侧可能造成用户看不懂的样式跳变。
- 小白案例：在红色和蓝色笔迹交界处插字，必须先说明新字要用哪种颜色。

### C04. 空排版元素导致输入位置不确定

- 用户触发：在空的排版标签附近输入。
- 系统条件：浏览器光标位置与源码插入位置可能不一致。
- 当前文案：标题“这里暂时不能直接改字”；正文说明旁边有空排版元素。
- 操作按钮：“添加评论”。
- 用户操作：选择其他明确文字，或添加评论交给 AI。
- 为什么提醒：继续输入可能把字放到错误标签里。
- 小白案例：两个空盒子挨在一起，系统不知道你想把物品放进哪一个。

### C05. 复杂网页结构不能直接改字

- 用户触发：在包含特殊嵌套、组件边界或必须保留结构的内容中输入。
- 系统条件：最小 Source Patch 无法在不伤害结构的前提下完成。
- 当前文案：标题“这里暂时不能直接改字”；正文“这段内容里有需要保留的网页结构……”
- 操作按钮：“添加评论”。
- 用户操作：用评论说明修改目标。
- 为什么提醒：复杂修改适合走经过完整验证的 AI 版本链。
- 小白案例：普通文本像便签，复杂组件像机械表，不能用同一种方式拆。

### C06. 特殊布局导致光标可能错位

- 用户触发：编辑使用 transform、zoom、多栏、flex、grid 或特殊盒模型的文字。
- 系统条件：视觉光标与源码选择映射不够可靠。
- 当前文案：标题“这里暂时不能直接改字”；正文“这段文字的排版比较特殊……”
- 操作按钮：“添加评论”。
- 用户操作：仍可选中文字调整安全样式，复杂内容改用评论。
- 为什么提醒：视觉位置相同不代表源码位置相同。
- 小白案例：镜子里的位置和真实物体位置不同，不能只看镜像下手。

### C07. 多行粘贴

- 用户触发：在直接编辑状态粘贴包含换行的文本。
- 系统条件：当前结构可以精确映射时正常写回；只有实际无法建立安全 Source Patch 时才进入统一编辑受阻提示。
- 当前文案：支持时无提醒；不支持时使用 C02 的统一说明，底层详情保留“当前结构暂不支持多行粘贴”供诊断。
- 用户操作：支持时照常编辑；真正受阻时可换一个明确文字位置，或添加评论。
- 为什么不单独提醒：多行本身不是错误，限制应以实际映射能力为准。
- 小白案例：替换一句话和插入三段新章节不是同一种编辑。

### C08. Enter、新增段落或换行

- 用户触发：按 Enter 或执行新增段落。
- 系统条件：当前段落结构可以精确映射时正常创建最小结构 Patch；无法证明位置时才停止。
- 当前文案：支持时无提醒；不支持时使用 C02 的统一说明，底层详情保留具体原因。
- 用户操作：支持时照常按 Enter；真正受阻时改用评论描述结构调整。
- 为什么不单独提醒：支持的正常输入不应被“安全策略”打断。
- 小白案例：改一行字可以直接做，拆成两个段落需要重新排版。

### C09. 图片、图标或组件不能这样删除

- 用户触发：用 Delete/Backspace 跨越非文字结构。
- 系统条件：删除范围包含图片、图标、嵌入组件或结构边界。
- 当前文案：标题“这处内容不能这样删除”；正文“请只修改文字，或添加评论说明要删除的图片、图标或组件。”
- 操作按钮：“添加评论”。
- 用户操作：缩小文字选择，或明确写评论。
- 为什么提醒：结构删除需要验证影响范围，不能按一次退格就完成。
- 小白案例：删掉一句文字和拆掉整张图片不是同一风险等级。

### C10. 输入法没有完整确认

- 用户触发：使用中文输入法时输入过程被中断或浏览器未完成 composition。
- 系统条件：无法证明候选文字已经完整提交。
- 当前文案：标题“已恢复输入前的文字”；正文“输入法没有完整确认这次输入。请点回文字后重新输入……”
- 操作按钮：“添加评论”。
- 用户操作：点回文字重新输入；重复失败时用评论。
- 为什么提醒：系统宁可恢复输入前状态，也不能保存半个候选词。
- 小白案例：拼音候选还没选完就切走，应用不应把半成品当最终文字。

### C11. 页面变化导致原文字位置漂移

- 用户触发：页面更新后继续编辑旧选择。
- 系统条件：源码节点、目标或唯一文本映射已经变化。
- 当前文案：标题“请重新选择这段文字”；正文“页面内容可能刚刚发生了变化……”
- 操作按钮：“添加评论”。
- 用户操作：再次点选目标，或添加评论。
- 为什么提醒：旧坐标不再可信。
- 小白案例：地图更新后道路编号变了，需要重新点一次目的地。

### C12. 当前文字输入尚未结束

- 用户触发：输入法或文字编辑尚未完成时点击预览、项目、保存、发送等跨流程操作。
- 系统条件：编辑 checkpoint 不能安全提交。
- 当前文案：标题“当前文字还在处理中”；正文优先显示具体原因，默认“请点回文字完成输入；已输入的内容仍保留在画布中。”
- 操作按钮：无。
- 样式与时长：警告色，5 秒。
- 用户操作：点回当前文字，完成或取消输入，再继续原操作。
- 为什么提醒：用户已经在正确位置，额外“重试”按钮不能改变输入法状态。
- 小白案例：一句话还没打完时切换文档，先把光标放回去收尾即可。

## 10. 原位持久提醒与决策

### I01. 上次打开的 HTML 无法恢复

- 位置：页面顶部持久横幅。
- 用户触发：启动源页。
- 系统条件：上次活动文件已移动、删除、损坏或不可读。
- 当前文案：“上次打开的 HTML 无法恢复”“文件可能已移动、删除或损坏。源页没有打开其他内容来替代它。”
- 操作按钮：“选择其他 HTML”“暂时关闭”。
- 用户操作：选择其他文件，或关闭提示后继续使用欢迎页。
- 为什么原位显示：这是启动上下文，不应以短 Toast 一闪而过。
- 小白案例：书签指向的文件不见了，应用不能随便打开另一份文件冒充。

### I02. 本地项目资料服务不可用

- 位置：Canvas 上方持久横幅。
- 用户触发：正常编辑过程中本地 Bridge 停止。
- 系统条件：项目记录、附件或版本服务不可用。
- 当前文案：“本地项目资料暂时不可用”“当前页面内容仍保留。可先导出当前编辑，再重新打开源页。”
- 操作按钮：“导出当前编辑”“重新打开源页”。
- 用户操作：有未保存内容时先导出；安全后重新打开。
- 为什么原位显示：问题持续影响当前页面，需要一直保留恢复入口。
- 为什么不再弹原生窗口：Renderer 已能显示完整恢复路径，重复弹窗会打断用户。
- 小白案例：文件柜服务断开，但桌面上的纸还在；先复印一份，再重启文件柜。

### I03. 源 HTML 外部冲突或写入失败

- 位置：Canvas 上方持久横幅。
- 用户触发：直接编辑后自动保存，或外部程序同时修改源文件。
- 系统条件：检测到磁盘内容变化、权限问题或写入失败。
- 当前标题：“源 HTML 已被外部修改”或“当前修改还没有写入文件”。
- 当前正文：保留具体错误；默认强调“工作台保留了当前编辑内容，不会假装已经更新。”
- 操作按钮：“导出当前编辑”“重新载入外部文件”。
- 用户操作：先导出当前内存内容，再决定是否载入外部文件。
- 为什么原位显示：这是当前 HTML 的长期安全状态，不应被关闭后失去入口。
- 小白案例：Word 检测到文件被别人改过，需要一直保留另存和重新载入入口。

### I04. 当前项目暂不可编辑

- 位置：右侧评论栏顶部状态卡。
- 用户触发：打开项目。
- 系统条件：项目状态、版本或评论记录读取失败。
- 当前文案：“当前项目暂不可编辑”加具体错误。
- 操作按钮：“重试读取”。
- 用户操作：确认文件仍存在后重试。
- 为什么原位显示：项目读取问题直接影响评论栏和编辑权限，入口就在当前项目。
- 小白案例：档案夹目录没读出来，先在档案夹区域重读，不需要全屏弹窗。

### I05. 评论还没有安全记录

- 位置：右侧评论栏。
- 用户触发：添加、编辑、删除评论或附件。
- 系统条件：评论草稿写入失败。
- 当前文案：“评论还没有安全记录”“本轮评论暂时无法记录；当前内容仍保留在页面中。”
- 操作按钮：“重试记录”。
- 用户操作：从评论栏重试。
- 为什么原位显示：问题只属于评论持久化，用户无需离开评论。
- 小白案例：聊天草稿没同步到云端，提示应留在输入框旁。

### I06. 项目记录文件内容没有读取成功

- 位置：项目抽屉的文件查看页。
- 用户触发：打开 `PROJECT.md`、运行状态、Prompt、修改要求或其他记录。
- 系统条件：自动读取后仍失败。
- 当前文案：小标题为文件类型；标题“内容没有读取成功”；正文为可读错误。
- 操作按钮：“重试读取”；同时保留“返回项目”。
- 用户操作：重试，或返回项目继续其他工作。
- 为什么原位显示：错误对象就是当前文件页。
- 小白案例：一本资料册某页打不开，重读这一页即可，不必关闭整个应用。

### I07. 项目规则保存失败

- 位置：`PROJECT.md` 编辑器下方。
- 用户触发：自动保存、关闭规则页、切换项目或关闭应用。
- 系统条件：写入失败且回读内容不一致。
- 当前文案：默认“项目规则暂时没有保存；内容仍保留在这里，可以再次保存。”
- 操作入口：仅在错误出现后显示“再次保存”；平时没有手动保存按钮。
- 用户操作：解决磁盘或服务问题后再次保存。
- 为什么原位显示：规则内容、错误和保存按钮需要同时可见。
- 小白案例：表单字段下面显示保存失败，比页面顶部再放一个“保存”按钮更清楚。

### I08. 最近打开记录读取或移除失败

- 位置：项目抽屉“最近打开”列表。
- 用户触发：打开项目抽屉，或移除一条最近记录。
- 系统条件：列表读取失败，或指定记录无法移除。
- 当前文案：“最近打开记录暂时无法读取。”或“这条最近打开记录暂时无法移除，可以重试。”
- 操作按钮：“重试读取”。
- 用户操作：在列表内重试；不影响当前项目。
- 为什么原位显示：问题只属于辅助列表。
- 小白案例：浏览历史加载失败，不应阻止当前网页继续使用。

### I09. 项目资料尚未建立

- 位置：项目抽屉“项目资料”区域。
- 用户触发：展开项目资料。
- 系统条件：项目登记或受控目录创建失败。
- 当前文案：“项目资料还没有建立”加具体错误。
- 操作按钮：“重试建立”。
- 用户操作：恢复本地服务后在原区域重试。
- 为什么原位显示：用户正在查看项目资料，恢复入口就在对象旁。
- 小白案例：新建文件夹失败时，在文件夹区域重试最自然。

### I10. AI 修改了评论范围外的内容（记录但不阻断）

- 位置：本轮处理面板。
- 用户触发：AI 返回完整 HTML。
- 系统条件：硬校验通过，但发现评论范围外的文字、属性、结构或样式变化。
- 当前文案：“已记录评论范围外的额外变化”；正文概括原因，并可展示少量 before/after 示例。
- 操作按钮：无；候选版本继续进入“打开最新版”。
- 用户操作：可以阅读审计说明，再按正常流程决定是否打开新版本。
- 为什么不再阻断：文字、属性、普通结构与样式联动是质量观察，不等于身份、脚本、协议或目标歧义等不可接受风险。
- 小白案例：你让装修客厅，方案顺带统一了相邻墙面的颜色；系统记录这件事供审阅，但不要求你先处理一条安全警报。

### I11. 外部 HTML 与 AI 候选冲突

- 位置：本轮处理面板。
- 用户触发：等待 AI 时，源文件被其他程序修改。
- 系统条件：外部版本和 AI 候选都有效。
- 当前文案：“请选择哪份内容成为当前 HTML”“外部文件和 AI 候选都已保留，系统不会静默覆盖任一侧。”
- 操作按钮：“采用 AI 候选”“保留外部内容”。
- 用户操作：根据已保留的两份内容选择一份。
- 为什么原位显示：这是内容归属决策，需要完整上下文，短 Toast 容纳不了。
- 小白案例：同一份文档出现两份不同修改，系统保存两份，让你决定合并方向。

### I12. 正在恢复未完成的版本事务

- 位置：本轮处理面板。
- 用户触发：异常退出后重新打开项目。
- 系统条件：检测到已经开始但未完成收口的安全事务。
- 当前文案：“正在恢复尚未保存完成的修改”“恢复完成前页面保持只读，评论和修改记录不会丢失。”
- 操作按钮：无。
- 用户操作：等待系统恢复。
- 为什么不弹全局提醒：下一步完全由系统负责。
- 小白案例：电脑重启后文档正在自动恢复，用户只需等待。

### I13. 本轮状态查询暂时失败（后台自动处理）

- 位置：本轮处理面板。
- 用户触发：等待 AI 或取消结果。
- 系统条件：某轮状态查询或取消结果暂时无法确认。
- 当前行为：下一轮继续自动核对，不累计成提醒，也不显示“重新打开源页”。
- 用户操作：无需操作；工作区整体不可用时，I02 才成为正式恢复边界。
- 为什么不提醒：查询失败不等于任务失败，重复提醒只会把后台恢复转嫁给用户。
- 小白案例：快递状态多次查不到时，订单页持续说明正在核对，而不是每几秒弹一次。

### I14. 正在确认 Request 是否已经建立

- 位置：本轮处理面板和底部状态区。
- 用户触发：发送请求后响应结果未知。
- 系统条件：存在重复提交风险。
- 当前文案：“正在确认这次发送是否成功”“源页会在后台继续核对，不会重复发送同一轮要求。”
- 底部状态：“正在自动确认发送结果…”或“等待下一次自动确认…”。
- 操作按钮：无；工作区整体不可用时由 I02 提供独立恢复入口。
- 用户操作：等待，不要再次发送。
- 为什么原位显示：用户最关心的是任务是否存在，本轮面板是权威位置。
- 小白案例：订单状态未知时持续查订单，不显示“再买一次”。

### I15. 最新版仍安全保留，但本次打开失败

- 位置：本轮处理面板。
- 用户触发：点击“打开最新版”。
- 系统条件：候选版本已经安全生成，但读取或显示步骤失败。
- 当前文案：“最新版仍已安全保留”“可在下方再次打开，不需要重新生成。”
- 操作入口：面板底部仍保留“打开最新版”。
- 用户操作：从原入口再次打开。
- 为什么原位显示：版本生成成功，不应误导用户重新跑 AI。
- 小白案例：包裹已经到仓库，只是柜门暂时打不开，不需要重新生产包裹。

### I16. 本轮没有可采用的变化

- 位置：本轮处理面板。
- 用户触发：AI 返回 `no-change`。
- 系统条件：结果与当前内容无有效差异。
- 当前文案：“这次没有可采用的变化”“没有创建新版本。原评论、附件和当前 HTML 都已保留。”
- 操作按钮：底部“返回编辑”“调整要求后重试”。
- 用户操作：返回编辑；如有需要，修改评论后重试。
- 为什么原位显示：这是本轮结果，不是错误弹窗。
- 小白案例：自动校对发现无需修改，告诉你结果并保留原稿。

### I17. 本轮结果未通过检查

- 位置：本轮处理面板。
- 用户触发：AI 返回。
- 系统条件：协议、身份、完整性、目标或其他硬校验失败。
- 当前文案：“本轮没有改动当前 HTML”加具体可读原因。
- 操作按钮：底部“返回编辑”“调整要求后重试”。
- 用户操作：查看原因、调整评论，再发起新一轮。
- 为什么原位显示：错误与本轮记录、步骤和原评论需要一起阅读。
- 小白案例：审核未通过时，结果应留在申请详情页，不应只弹一句“失败”。

### I18. 删除评论确认

- 位置：当前评论卡片内部。
- 用户触发：点击删除评论。
- 当前文案：“删除这条评论？”
- 操作按钮：“取消”“删除”。
- 用户操作：确认是否删除。
- 为什么原位显示：决定只影响这一张卡片，局部确认比全局模态框更清楚。
- 小白案例：删除一条聊天消息时，确认应出现在这条消息旁。

### I19. 应用更新已下载

- 位置：重启确认框；顶部发送按钮上方同时保留右对齐的红色斜体 `New! 重启更新`。
- 系统条件：用户点击 `New!` 或“关于源页”中的“下载更新”后，正式签名的 macOS App 已下载 stable 新版本。
- 当前文案：“现在重启并安装更新？”“源页会先确认当前编辑已安全写入，然后关闭并安装新版本。”
- 操作按钮：“稍后”“现在重启”。
- 用户操作：可以立即重启，也可以选择稍后继续编辑；稍后点击 `New! 重启更新` 会打开同一确认框。
- 安全结果：按钮仍走统一关闭排空；任何未写入内容都会取消安装并返回当前页面。普通退出不会安装。
- 克制边界：Canvas 不出现更新 NoticeBar，顶部不新增图标，下载不显示百分比、进度条或动画。
- 小白案例：更新包已经取到本机，但要等用户确认并收好当前工作后才换新版本。

### I20. 关于源页中的更新检查

- 位置：macOS 应用菜单“关于源页”弹层的更新卡片。
- 用户触发：打开“关于源页”，点击“检查更新”或“下载更新”。
- 系统条件：显示当前 stable 更新快照；手动检查时在同一位置进入等待状态，完成后更新为“已是最新”“可以下载”“正在下载”“可以安装”或可读失败原因。
- 当前文案：“正在检查更新”“当前已是最新版本”“发现 PageRoot <版本>”“PageRoot <版本> 已下载”；不可用时说明“暂时无法检查更新”或“此构建不支持自动更新”。
- 操作按钮：“检查更新”“重试检查”“下载更新”“重启更新”；旁边另有固定“在 GitHub 上查看”项目入口。
- 用户操作：可以主动检查、明确开始下载，或在下载完成后打开同一重启确认。
- 为什么原位显示：用户主动发起的查询需要持续、可复查的确定结果；不再额外发送一条短 Toast。自动检查失败仍保持静默，不打断编辑。
- 安全结果：手动检查与启动后、每 4 小时的自动检查复用同一主进程控制器；渲染器不能传入任意更新频道、下载地址或外部链接。
- 小白案例：像在应用“关于”页面里查看版本并按一次“检查更新”，结果一直留在刚才操作的位置。

## 11. 持续状态：不是提醒，但用户会看到

### S01. 文件保存状态

- 位置：窗口左上角和项目抽屉当前文件卡片。
- 状态文案：
  - “已安全保存”
  - “正在更新文件…”
  - “浏览器预览 · 只读”
  - “操作不会保存”
  - “检测到外部修改 · 未覆盖原文件”
  - “文件更新失败 · 尚未写入磁盘”
  - “已同步更新 · 时间”
- 为什么不是 Toast：保存状态持续变化，原位状态比重复弹出更可靠。
- 小白案例：云文档的“已保存”一直在标题旁，不会每次保存都弹通知。

### S02. Canvas 锁定或历史只读状态

- 位置：Canvas 内状态标记和顶部历史横幅。
- 状态文案：“本轮已锁定，仅可滚动浏览”“正在查看历史版本，只读”“正在预览已发送 HTML”“浏览器预览 · 只读”。
- 用户操作：按当前流程返回编辑或等待处理。
- 为什么不是警告：这是可预期模式，不是异常。
- 小白案例：查看 PDF 时显示“只读”，不需要弹错误。

### S03. Qoder 剪贴板交接状态

- 位置：顶部发送按钮和本轮流程。
- 状态文案：
  - “正在准备…”
  - “正在复制交接内容…”
  - “本轮要求已复制”
  - “复制失败 · 查看”
  - “交接内容已写入剪贴板”
  - “仅确认剪贴板写入成功，不代表 Qoder 已收到”
- 用户操作：复制失败时进入本轮面板，再从底部“重新复制本轮要求”。
- 为什么不是全局 Toast：按钮和流程板已经是权威状态来源。
- 小白案例：上传进度显示在上传按钮上，比另弹一个进度框更清楚。

### S04. AI 本轮七步流程

- 位置：本轮处理面板。
- 固定步骤：
  1. 本轮要求已冻结。
  2. 交接内容已写入剪贴板。
  3. 已检测到 AI 返回结果。
  4. 版本与文件完整性。
  5. 范围与质量校验。
  6. 新版本已安全保存。
  7. 打开最新版。
- 每一步显示等待、当前、完成、需要注意或错误，并在原位更新细节。
- 为什么不是 Toast：这是一段长流程，用户需要回看完整上下文。
- 小白案例：快递物流用一条时间线展示，不会每到一站弹一个窗口。

## 12. 浏览器确认弹窗

### B01. 离开浏览器预览（确认已取消）

- 当前行为：纯浏览器预览是正式只读能力，不能修改 PageRoot HTML，也没有待保存的编辑，因此离开时不询问。
- 页面自身交互：表单、脚本或临时页面状态可以运行，但顶部持续说明“操作不会保存”。
- 小白案例：在产品演示页里展开菜单不会改动产品源文件，离开时无需弹“是否保存”。

### B02. 重新载入会舍弃未写回修改

- 用户触发：存在本地未写回内容时点击重新载入。
- 当前文案：“重新载入会舍弃尚未写回的当前编辑内容。建议先导出副本，仍要继续吗？”
- 用户操作：取消后导出，或确认舍弃并载入磁盘版本。
- 为什么必须确认：这是明确的内容丢弃选择。
- 小白案例：刷新表单会清空未提交内容，需要先问一次。

### B03. 用历史版本替换当前 HTML（入口已取消）

- 当前行为：历史版本仅供只读查看，界面和 Bridge 都不提供恢复/替换操作，因此没有确认弹窗。
- 用户操作：可回到当前 HTML，或在 Finder 中查看历史文件。
- 小白案例：旧版档案可以翻阅，但不会从阅读页直接覆盖现行文件。

## 13. macOS 原生提示

### M01. 导出位置会覆盖当前源文件

- 用户触发：导出副本时选择了当前源 HTML、等价路径或硬链接。
- 当前文案：
  - 标题“请选择其他导出位置”
  - 主文案“HTML 副本不能覆盖当前源文件”
  - 详情“源文件保持不变。请更换文件名或文件夹后再导出。”
- 操作按钮：“重新选择位置”“取消”。
- 为什么使用原生提示：它发生在系统保存位置选择流程中。
- 小白案例：另存副本不能把原件覆盖掉。

### M02. 暂时无法安全关闭

- 用户触发：关闭窗口或退出应用。
- 系统条件：仍有本地更改未完成安全写入。
- 当前文案：“暂时无法安全关闭”“还有本地更改没有完成安全写入。”
- 操作按钮：“继续编辑”。
- 为什么使用原生提示：关闭请求已经离开 Renderer 主流程，应用必须阻止退出。
- 小白案例：文档仍在保存时，系统拒绝立刻关机。

### M03. 关闭协调本身异常

- 用户触发：退出应用。
- 系统条件：关闭协调代码抛出未预期错误。
- 当前文案：标题“无法安全关闭源页”；详情为系统错误。
- 操作按钮：系统默认关闭错误框。
- 为什么使用原生提示：Renderer 或关闭链路不再可靠。
- 小白案例：门锁控制器自己故障时，只能由系统级警报说明。

### M04. 重新打开前仍有未写入内容

- 用户触发：点击“重新打开源页”。
- 系统条件：关闭检查发现当前页面仍有未写入内容。
- 当前文案：“重新打开前还需要一步”“当前页面还有内容没有完成安全写入。”
- 操作按钮：“返回源页”。
- 为什么使用原生提示：重启会销毁当前 Renderer，必须在应用层拦截。
- 小白案例：重启电脑前发现文档未保存，先返回文档处理。

### M05. 重新打开协调本身异常

- 用户触发：重新打开应用。
- 系统条件：重启协调失败。
- 当前文案：标题“暂时无法重新打开源页”；详情为系统错误。
- 为什么使用原生提示：重启边界已经超出当前页面能力。
- 小白案例：系统重启命令本身失败，需要由操作系统层面告知。

### M06. 本地项目服务停止，且 Renderer 尚不可用

- 用户触发：启动或早期恢复过程中 Bridge 停止。
- 系统条件：页面还没有加载到能显示应用内横幅的阶段。
- 当前文案：
  - 标题“本地项目资料暂时不可用”
  - 主文案“源页的本地项目服务已停止。”
  - 详情说明当前窗口内容仍保留。
- 操作按钮：“返回源页处理”“重新打开源页”。
- 为什么使用原生提示：此时应用内 UI 还不能承担恢复。
- 去重规则：Renderer 一旦加载，改用 I02，不再显示本原生提示。
- 小白案例：店内广播系统没启动，只能先用门口告示。

### M07. 源页启动失败

- 用户触发：启动应用。
- 系统条件：主窗口或关键启动流程抛出错误。
- 当前文案：标题“源页启动失败”；详情为启动错误。
- 后续：显示错误后退出。
- 为什么使用原生提示：正式界面根本没有建立。
- 小白案例：应用连首页都打不开，只能由系统错误框说明。

## 14. 代码中存在、但当前不会弹出的消息

这些调用会进入 `setToast`，但没有显式声明 `direct-action`、`user-choice` 或 `background-result`，因此被 `shouldPresentNotice` 过滤。它们仍值得记录，因为测试和未来改动需要知道“为什么没出现”。

### N01. 更新页面没有打开

- 定义文案：“更新页面没有打开”“当前内容不受影响；可以重新打开 PageRoot 发布页。”
- 当前结果：不弹出。
- 用户仍可操作：顶部 Update 徽标仍在，可再次点击。
- 设计理由：更新页面是辅助入口，不应盖过当前编辑。

### N02. 已恢复上次未写回的编辑

- 定义文案：“已恢复上次未写回的编辑”“工作台正在把异常退出前的内容安全更新到源 HTML。”
- 当前结果：不弹出。
- 实际反馈：保存状态在标题栏原位更新。
- 设计理由：恢复成功不需要打断用户。

### N03. 评论附件副本清理失败

- 定义文案：“附件已从评论移除”“项目中的附件副本暂时无法清理。”
- 当前结果：不弹出。
- 实际结果：附件已从当前评论移除；残留清理由项目记录负责。
- 设计理由：用户主任务已经完成，不为后台清理制造阻断。

### N04. HTML 副本导出成功

- 定义文案：“已导出 HTML 副本”；桌面路径还会显示保存文件名。
- 当前结果：不弹出。
- 实际反馈：导出对话框与目标文件已经提供结果。
- 设计理由：成功动作不需要额外遮挡 Canvas。

### N05. 外部文件重新载入成功

- 定义文案：“已重新载入外部文件”“工作台现在显示磁盘上的最新内容。”
- 当前结果：不弹出。
- 实际反馈：Canvas 内容和冲突横幅直接变化。
- 设计理由：页面变化本身就是更强的成功证据。

### N06. Qoder 交接内容复制失败

- 定义文案：“交接内容还没有复制”“本轮 Request 已保留；请打开处理详情后重试复制。”
- 当前结果：不弹出。
- 实际反馈：顶部按钮变为“复制失败 · 查看”，本轮流程显示“交接内容尚未复制”，底部提供“重新复制本轮要求”。
- 设计理由：同一问题已有三个原位信号，不再重复全局提示。

### N07. 当前项目打开了有协议警告的候选版本

- 定义文案：“版本 N 已打开，但需要检查”；说明临时输出在最终化后发生变化，但已提交版本未受影响。
- 当前结果：不弹出。
- 实际反馈：警告保留在本轮处理记录。
- 设计理由：版本已安全打开，详情适合回到审计面板查看。

### N08. AI 候选已取消

- 定义文案：“版本 N 已取消”“对应项目的评论仍然保留，迟到的完成信号不会被接纳。”
- 当前结果：不弹出。
- 实际反馈：处理面板收口并恢复编辑。
- 设计理由：取消成功属于当前操作的自然结果。

### N09. 已选择保留外部 HTML

- 定义文案：“已保留外部 HTML”“AI 候选没有覆盖源文件……”
- 当前结果：不弹出。
- 实际反馈：冲突面板关闭，Canvas 读取外部内容。
- 设计理由：用户刚作出的选择不需要再次通知确认。

### N10. 历史内容已设为当前 HTML（定义已删除）

- 当前结果：界面和 Bridge 都没有历史回写入口，也不再保留对应成功消息。
- 设计理由：历史版本是只读审阅能力，不应产生覆盖当前源码的旁路。

### N11. 延迟后会自动继续的项目切换状态

- 定义文案包括：
  - “正在准备本轮任务”“当前操作结束后会自动打开目标项目。”
  - “正在核对当前画布”“核对完成后会自动打开目标项目。”
  - “检测到新的画布修改”“新修改保存后，会自动打开目标项目。”
- 当前结果：不弹出。
- 实际反馈：目标项目意图被系统记录，条件解除后自动继续。
- 设计理由：没有用户动作，弹出只会让用户误以为需要处理。

## 15. 为什么有些地方仍保留“重试”

“不显示重复重试 Toast”不等于产品中不能有任何重试。当前允许的重试必须满足至少一个条件：

1. 它位于失败对象旁，例如评论栏“重试记录”、文件页“重试读取”。
2. 第一次动作没有产生不可重复的写入，例如读取最近项目。
3. 系统已经明确确认原操作没有成功，例如 Request 明确未建立。
4. 重试会改变条件或走新的安全路径，例如“重新选择位置”。

以下重试被禁止：

- Request 结果未知时再次提交。
- 写入结果未知时再次写入。
- 取消结果未知时再次取消。
- 原入口仍清晰可见时，再在 Toast 中复制一个同义按钮。

## 16. 文案结构规则

每条异常文案按以下顺序写：

1. 标题：发生了什么。
2. 正文第一句：哪些内容已经安全保留或没有被修改。
3. 正文第二句：如果用户必须行动，明确说下一步。
4. 按钮：写清对象和结果，不使用脱离上下文的“处理”“查看”“重试”。

推荐：

- “副本没有导出。当前源 HTML 没有被改动。请选择其他位置。”
- “已记录评论范围外的额外变化。新版本仍可按正常流程打开。”
- “评论和附件仍保留；重新选择画布位置即可继续。”

不推荐：

- “操作失败。”
- “请重试。”
- “处理第一条。”
- “无视本校验，继续。”
- “未知错误：runtime-state revision hash mismatch。”

技术错误在展示前会移除 Electron IPC 前缀、异常类名、堆栈，并把 `runtime-state`、`revision`、`hash` 转成“项目运行状态”“编辑状态”“内容校验”。可见错误最长约 280 字。

## 17. 维护与测试要求

新增或修改提醒时，必须同时回答：

1. 系统能否自动恢复？
2. 这条信息是否已经能在原控件显示？
3. 用户是否必须改变条件或作决定？
4. 按钮是否改变失败条件，而不是原样重复动作？
5. 消息关闭后，真实问题是否仍有原位状态？
6. 是否明确说明原文件、评论、附件或候选版本是否安全？
7. 是否使用普通用户语言？
8. 是否有聚焦、键盘和屏幕阅读器语义？

主要代码位置：
